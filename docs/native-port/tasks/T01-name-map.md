# T01. Карта имён Xbox ↔ Android: доводка и проверка

**Этап:** знание · **Зависит от:** — · **Объём:** большой · **Меняет поведение игры:** нет

## Цель

Достоверная таблица «адрес Xbox → имя метода» с уровнем уверенности, которому можно
доверять при написании хуков и нативного кода. Важнее точность, чем покрытие.

## Текущее состояние

Предыдущая сессия оборвалась по лимиту и оставила черновик:

- `scripts/name_xbox_from_android.py` (901 строка, не в git): RTTI Xbox и Android, перевод
  слотов Itanium → MSVC, выравнивание слотов Needleman–Wunsch, имена по строкам и по вызовам.
- `research/cross-platform/xbox-android-names.json`: 943 имени из 20 999 функций
  (vtable 729, vtable-synth 24, strings 166, propagated 24; high 440, medium 340, low 163).
  Сопоставлено 129 классов из 185 Xbox-классов с vtable.

Проверка черновика **не пройдена**:

| Признак | Значение |
|---|---|
| Якоря из комментариев `src/` | совпало 13 из 21 |
| `gChallengeDefs` | 94/94 (таблица, не функции) |
| Слоты ввода `Sexy::Widget` 53–60 | 8/8 |
| Проверка по общим строкам, high | 7 подтверждено, **2 противоречат** |
| Проверка по общим строкам, low | 5 подтверждено, 7 противоречат |

Расхождения якорей, которые нужно разобрать (адрес | имя в `src/` | имя черновика):

- `0x82473000` | `Widget::GamepadButtonDown` | `Sexy::Widget::MouseDown(int,int,int)`, **high** — вероятная ошибка выравнивания: у Xbox `Widget` 71 слот, у Android 121.
- `0x82188E20` | `DialogButton::Resize` | `GameButton::Resize`, high — не тот класс или неверное имя в `src/`.
- `0x82189B40` | `Controls::UpdateInput` | `BaseGamepadControls::Update(float)`, high.
- `0x82190D80` | `GamepadControls::SetState` | `BaseGamepadControls::GotoState`, medium.
- Остальные (`UpdateHeavyWeapon`/`HeavyWeaponUpdate`, `ButtonDown`/`OnButtonDown`, `PlaySample`/`PlaySampleSingle`) похожи на разницу в названиях, которые дали авторы порта. Проверка совпадения должна это учитывать, а не считать ошибкой или успехом автоматически.

Также: разбор шаблонных MSVC-имён RTTI сломан (`std::::::std::D::DU?$char_traits…` в
`unmatched_xbox_classes`).

## Что сделать

1. Разобрать каждое расхождение якорей: открыть обе функции, решить, кто прав — черновик или
   комментарий в `src/`. Записать вывод с доказательством.
2. Найти причину ошибок high-уровня (выравнивание `Sexy::Widget` и наследников, вероятно,
   первым) и исправить метод, а не отдельные случаи.
3. Пересмотреть шкалу уверенности. **high** — только при двух независимых признаках:
   например, слот vtable и совпадение строк/констант/последовательности вызовов.
4. Добавить независимый контрольный набор: не меньше 40 функций, размеченных вручную по
   Xbox-коду (строки assert, уникальные константы, вызовы известных функций). Набор хранить
   в `docs/native-port/data/name-map-golden.json` с доказательством для каждой записи.
   Метод не должен его использовать — только для оценки.
5. Починить разбор шаблонных RTTI-имён MSVC или явно исключить `std::`/CRT из рассмотрения.
6. Только после этого — расширять покрытие (распространение по вызовам и т. п.).

## Критерии приёмки

- [ ] Все 21 якорь разобраны; для каждого записано, кто прав и почему.
- [ ] На контрольном наборе: точность high = 100 %, точность medium ≥ 90 %. Числа считает скрипт.
- [ ] Проверка по общим строкам: ни одного противоречия на уровне high.
- [ ] Число high + medium имён указано и пересчитывается командой из отчёта.
- [ ] Анализатор детерминирован: два прогона дают одинаковый вывод (сравнить SHA-256).
- [ ] Вывод содержит SHA-256 всех входов.
