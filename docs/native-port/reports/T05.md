# T05 — снимки состояния и сравнение реплеев

## 1. Итог

Добавлены отключённая по умолчанию запись JSONL после логического шага, строгий
покадровый компаратор и запуск пяти существующих реплеев с копиями профилей.
**Все пять пар недетерминированы с кадра 0**: отличается RNG; источник seed и
доставка событий по времени разобраны ниже. Это результат исследования, а не
доказательство эквивалентности будущей нативной замены. Инструменты готовы к
независимой приёмке: CTest **12/12**, обычные регрессии **276/276** после
согласованного обновления устаревших UI-реплеев и ожидания навигации Help.

## 3. Как воспроизвести

Из корня проекта, с подготовленным `runtime-data/zen-shop-probe-user`:

```powershell
.\build.bat
.\build.bat test
python -I scripts/compare_state_dumps.py --self-test

.\scripts\run_determinism_check.ps1 -OutputRoot runtime-data/state-dumps/review-pairs
.\scripts\run_determinism_check.ps1 -Cases minigame -Repeats 1 -Sensitivity -OutputRoot runtime-data/state-dumps/review-sensitivity
.\scripts\run_determinism_check.ps1 -Cases minigame -Repeats 1 -ProfileOnly -OutputRoot runtime-data/state-dumps/review-profile

python -I scripts/compare_state_dumps.py runtime-data/state-dumps/review-pairs/adventure-1/state.jsonl runtime-data/state-dumps/review-pairs/adventure-2/state.jsonl

# Без новых флагов:
.\scripts\run_feedback_regression.ps1
python scripts/check_feedback_regression.py
.\scripts\run_multiplayer_regression.ps1
python scripts/check_multiplayer_regression.py
.\scripts\run_services_regression.ps1
python scripts/check_services_regression.py
.\scripts\run_shop_regression.ps1
python scripts/check_shop_regression.py
```

Компаратор возвращает 1 при различии — для текущих пяти пар это ожидаемый результат,
2 при негодном захвате. Runner принимает исследовательское различие, но отвергает
ошибки схемы, отсутствие целевого игрового режима, неполный реплей и повреждённые
массивы. Результаты записываются в новые каталоги, прежние захваты не перетираются.

Сохранённые доказательства текущего запуска:

- `runtime-data/state-dumps/t05-final/summary.json` — Adventure/Versus/мини-игра;
- `runtime-data/state-dumps/t05-ui-pairs/summary.json` — актуальные пары Zen/меню;
- `runtime-data/state-dumps/t05-sensitivity/`;
- `runtime-data/state-dumps/t05-profile/`;
- `runtime-data/state-dumps/t05-regressions/` — полные первоначальные наборы;
- `runtime-data/state-dumps/t05-ui-update/` — повторные services, финальный аудит,
  SHA-256 входов и архив исходных реплеев/проверки до обновления в `before/`.

Эти крупные данные игнорируются git. Runner фиксирует хеши EXE, исходников,
реплеев, профиля, игрового образа, настроек и самого инструмента. Каждый дамп
содержит SHA-256 манифеста; компаратор считает SHA-256 обоих дампов.
EXE: `61653da121d89ebcb528e34524394a41ee76061c97c8ede9523fc7810eca2a40`.
XEX 0.0.1.4: `46aa9531a4091be2fdeb532a14a0f31c5547d248a6868d9f7d65b119b2005d21`.

## 4. Результаты

### Сборка и читатель

**Проверено запуском:** сборка успешна, генератор не переписывал Xbox-исходники;
CTest — **12/12**. Новые тесты проверяют живые/свободные/мёртвые слоты, изменение
здоровья и одного бита позиции, независимость от адреса выделения, неверные счётчики,
null/unmapped/переполнение диапазона; компаратор проверяет совпадение, разницу,
длину, разрывы нумерации, типы и обрезанный файл.

**Проверено по Xbox:** stride/ID/поля четырёх DataArray, глобальный MT RNG с 624
словами и индексом, точка обновления. Адреса и способ повторения разбора перечислены
в `state-dumps.md`. Обход вызывается после оригинала; `UpdateAllF` исключён.
Без dump/profile путь ограничен переходом в оригинал и проверкой сохранённых bool.

### Детерминизм пяти пар

**Проверено запуском**, по два отдельных процесса с одинаковыми исходными профилями
и реплеем, без искусственного изменения состояния:

| Сценарий / реплей | Шагов в каждом | Игровых шагов целевого mode A/B | Первое различие | Результат / причина |
|---|---:|---:|---|---|
| Adventure / `adventure_mouse.csv` | 5000 | 1887 / 1883 (mode 0) | 0, `rng_hash` | Разошлось; seed из uptime, доставка ввода по времени |
| Versus / `feedback_vs_two_pads.csv` | 6000 | 3256 / 3260 (mode 76) | 0, `rng_hash` | Разошлось; те же источники |
| Heavy Weapon / `feedback_heavy_console.csv` | 3000 | 1845 / 1848 (mode 20) | 0, `rng_hash` | Разошлось; те же источники |
| Zen Garden / `services_zen_regression.csv` | 5000 | 4383 / 4378 (mode 44) | 0, `rng_hash` | Разошлось; те же источники |
| Меню / `services_menus_regression.csv` | 5000 | Board отсутствует | 0, `rng_hash` | Разошлось; RNG и момент UI-событий |

«Игровые шаги» требуют `board=true, scene=3`, а не просто существования Board:
Adventure до старта содержит демонстрацию mode 73. В мини-игре наблюдались зомби
и снаряды, в Zen — растения/монеты; нулевое число растений Heavy Weapon штатно.
Все десять выбранных для таблицы запусков завершились, захваты имеют ожидаемую
длину и прошли самосравнение. Первые три пары взяты из `t05-final`, Zen/меню —
из `t05-ui-pairs` после обновления CSV; EXE и код диагностики одинаковы.
Строгое сравнение не исключает RNG: во всех пяти актуальных парах первое поле —
`rng_hash` на кадре 0. Проверка целевого режима и длины захвата проходит.

В частотах `differing_fields` присутствуют также UI, создание Board и поля объектов.
Исключение RNG не делает реплеи пригодными для доказательства нативной замены.
Таблица фиксирует наблюдение конкретных запусков; при повторении времена переходов,
числа игровых шагов и значения RNG могут измениться.

**Проверено по Xbox:** app init `82482080..88` вызывает `822CA100`, сохраняет
возвращённое слово и передаёт его в seed wrapper `824943A0`. Getter читает импорт
`82000850` и поле `+10` hex. В образе импорт имеет ordinal AD — `KeTimeStampBundle`.
**Подтверждено локальным исходником SDK:**
`research/rexglue-source/src/kernel/xboxkrnl/export_table.inc:187` и
`xboxkrnl_module.cpp:183..199` связывают его с `QueryGuestUptimeMillis()` и таймером
обновления 1 мс. Разный момент запуска даёт возможность разного seed.

**Проверено по исходнику порта:** `StartInputReplay` в `src/input_replay.cpp`
работает в `std::jthread`, использует `steady_clock` и опрос каждые 25 мс,
а ожидания готовности сдвигают начало временной шкалы. События не привязаны к номеру
шага симуляции. **Вывод:** фиксированный seed сам по себе не гарантирует равенства;
для будущего диагностического режима нужна также доставка ввода по шагам.
Точная доля каждого источника в каждом позднем расхождении не изолирована.

### Чувствительность и стоимость

**Проверено запуском:** `t05-sensitivity/minigame-1/sensitivity.json`:
первое и единственное различие — **кадр 1800, `sun`, 1000 → 1001**.
В логе есть `PvZ state sensitivity applied +1 sun at frame 1800`.
Контрольный и изменённый потоки имеют по 3000 полных шагов. Изменено значение
в guest-памяти, а не готовый JSON; сравнивается снимок до записи и после неё.

**Проверено запуском:** Heavy Weapon, два процесса по 52 с, одинаковый исходный

## 6. Не проверено и риски

- Нативных замен в T05 нет. Равенство выбранных полей не доказывает полную
  эквивалентность: отсутствуют щиты/шлемы, все таймеры, challenge/UI/input queue и
  RNG отдельных объектов. Поля нужно расширять под конкретную замену.
- Дампы ограничены фиксированным числом шагов, чтобы сравнение не зависело от
  миллисекунды остановки процесса. Реплей после лимита продолжает работать;
  покрытие дампа ограничено указанным окном и не обещает запись всех поздних действий.
- FNV-1a64 допускает коллизии. В хеш включены ID и порядок слотов, исключены
  указатели, padding и свободные объекты; float сравниваются по исходным битам.
- Проверки отображения памяти реализованы для Windows; на других платформах
  остаются только границы u32 и счётчики. Другие платформы не запускались.
- Чувствительность сравнивает фактическое состояние до/после одной записи внутри
  одного процесса. После вмешательства контрольный поток тоже наблюдает изменённую
  игру; это не независимая контрольная симуляция.
- Автоматические реплеи не заменяют физические геймпады, прослушивание звука,
  субъективную оценку плавности и полное прохождение игры.
- Диагностическое фиксирование seed/ввода в этой задаче не реализовано;
  недетерминизм не скрывается пропусками полей или подгонкой номеров кадров.
