# T06. Механизм нативной замены и пилот на чистой функции

**Этап:** пилот · **Зависит от:** T01, T04, T05b (все принятые; T05 показала, что без T05b реплеи недетерминированы) · **Объём:** средний · **Меняет поведение игры:** только под флагом

## Цель

Отработать полный цикл на одной функции: имя (T01) → структуры (T04) → нативный C++ →
переключатель → сравнение реплеев (T05). Цикл станет шаблоном для всех следующих замен.

## Выбор функции

Кандидат должен быть чистым или почти чистым: без собственного состояния, с небольшим
числом вызовов, часто вызываемым в обычной игре. Примеры для проверки по T01:
`Board::GridToPixelX/Y`, `Board::PixelToGridX/Y`, `Board::PlantingPixelToGridX/Y`,
`Plant::GetCost`, `Zombie::GetZombieRect`. Выбрать одну с именем high, обосновать выбор в отчёте.

## Что сделать

1. Механизм: `REX_HOOK_RAW` для выбранной функции. При `--pvz_native_<name>=true` работает
   нативная реализация, иначе — `__imp__` оригинала. Для отладки — режим «оба»: вызвать
   обе, сравнить результаты, расхождение писать в журнал с аргументами.
2. Нативная реализация — на структурах `src/xbox/*.h` из T04, без ручных смещений. Источник
   логики — Xbox-код. PC (MIT) можно взять за основу; мод GPL — нет.
3. Прогнать режим «оба» на реплеях из T05 и на `Edge-Tests`, где функция вызывается.
   Записать число вызовов и расхождений.
4. Прогнать реплей с заменой и без, сравнить снимки T05.
5. Описать шаблон: `docs/native-port/replacement-howto.md` — шаги, макросы, как проверять.

## Результат

`src/native/<name>.cpp` (+ `CMakeLists.txt`), `docs/native-port/replacement-howto.md`,
`docs/native-port/reports/T06.md`.

## Критерии приёмки

- [ ] Режим «оба»: 0 расхождений; указано число сравнённых вызовов (не меньше 10 000) и покрытые реплеи.
- [ ] Снимки T05 с заменой и без совпадают на всех реплеях, где T05 показала детерминизм.
- [ ] Искусственная ошибка в нативной версии ловится режимом «оба» (показать в отчёте).
- [ ] Без флага поведение по умолчанию не меняется; `.\build.bat test` и регрессии проходят.
