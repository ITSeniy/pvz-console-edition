# T01b. Подтверждение имён vtable вторым признаком

**Этап:** знание · **Зависит от:** T01 (принята с замечаниями) · **Объём:** средний · **Меняет поведение игры:** нет

## Цель

После T01 экспортировано 133 имени, но 132 из них получены по уникальным строкам. Метод
vtable дал одно medium-имя; 740 кандидатов остались low. Консольных классов ввода и меню
(`GamepadControls`, `BaseGamepadControls`, `ZenGardenControls`, `TreeOfWisdomControls`,
`MainMenu`, `VSSetupMenu`, `LawnMenuWidget`, `Sexy::Widget`) в экспорте почти нет, а они
нужнее всего для T04 и T07. Задача — поднять до medium те low-кандидаты vtable, которые
подтверждаются **вторым, независимым** признаком. Точность важнее числа.

## Допустимые вторые признаки

- Совпадение порядка вызовов уже названных функций (high/medium из T01) в теле функции на обеих платформах.
- Совпадение уникальных констант (номера звуков, ID ресурсов, номера кнопок и режимов),
  кроме тривиальных (0, 1, −1, степени двойки до 256).
- Совпадение структуры с PC-исходником (MIT) для общих классов: последовательность вызовов
  и констант в функции с тем же именем.
- Вызов из уже названной функции в позиции, совпадающей с Android.

Размер, форма и пустое тело — только для поиска кандидатов, не для подтверждения.

## Что сделать

1. Дописать в `scripts/name_xbox_from_android.py` (или отдельный модуль рядом) шаг
   подтверждения. Повышение до medium — при одном втором признаке, до high — при двух.
   Повышения не распространяются рекурсивно в одном прогоне.
2. **Новый контрольный набор**, не пересекающийся с golden T01:
   `docs/native-port/data/name-map-golden-2.json`, не меньше 30 функций, из них не меньше
   15 из перечисленных консольных классов. Набор составляется **до** доработки метода,
   фиксируется в отчёте с SHA-256 и потом не меняется.
3. Пересчитать точность на обоих наборах.

## Результат

Доработка анализатора, обновлённый `docs/native-port/data/xbox-names.csv`,
`docs/native-port/data/name-map-golden-2.json`, `docs/native-port/reports/T01b.md`.

## Критерии приёмки

- [ ] Golden-2 зафиксирован до изменений метода (SHA-256 и время — в отчёте; файл не менялся после).
- [ ] На golden-2: high — 100 %, medium — не ниже 90 %. На старом golden — не хуже T01.
- [ ] Не меньше 40 новых имён medium/high в перечисленных консольных классах; если не получилось — объяснение, что мешает.
- [ ] Для каждого повышенного имени в `evidence` записан второй признак.
- [ ] Детерминизм вывода и SHA-256 входов — как в T01.
