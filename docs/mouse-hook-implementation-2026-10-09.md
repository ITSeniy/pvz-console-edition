# Изменения mouse hook — 9 октября 2026

По результатам [аудита](mouse-hook-audit-2026-10-09.md) исправлен транспорт
мыши и добавлены проверки, обнаруживающие ошибки до нативного запуска.

## Поведение

- Позиция, кнопки, колесо и отмена проходят через `MouseInputStream` в порядке
  публикации. Движение после отпускания не выполняется при старом удержании.
  Траектория drag сохраняется, включая движения туда и обратно между кадрами.
- Update/draw hooks читают последнюю **обработанную** позицию. Новые события
  UI не заменяют её до прохождения диспетчера.
- Потеря фокуса, выход указателя, контроллер, смена PC/Console, отключение
  абсолютной мыши и переполнение отменяют старое поколение ввода.
  Старые клики/колесо удаляются; отпускание без соответствующего нажатия
  не вызывает игровое действие.
- Колесо сохраняет координаты и место относительно кликов. Дробный остаток
  сбрасывается при отмене и переходе на другой экран.
- `CancelMouseGestures` сбрасывает custom captures перед нативными callbacks.
  Живая кнопка очищается независимо от hover, включая hidden/disabled.
  Прерванное удержание Console-лопаты не завершается копанием.
- После нативного MouseUp экран и widget разрешаются заново. Отпускание,
  которое уже закрыло экран, не направляется повторно в новый экран.
- Очередь извлекается по одному событию. Нативные покупки с вложенным modal
  loop продолжают получать ввод, а ссылки на старый пакет не удерживаются.

## Повторное использование

`guest_memory.h` задаёт общие чтение/запись Xbox big-endian значений через
`memcpy`, включая невыровненные адреса. Его используют три mouse-адаптера.
`widget_tree.h` содержит общий обход с ограничениями глубины/числа узлов,
поиск живого widget и учёт скрытых родителей. Его используют поиск
потомков, синхронизация hover и отмена захвата.

Игровые стоимость, cooldown, допустимость посадки, покупка, сбор и действия
инструментов выполняются исходными Xbox-функциями.

## Реплеи

`replay_event.h` содержит одну таблицу имён/типов действий. Парсер до запуска
проверяет конечность чисел, временной порядок, диапазоны controller/fixture
и структуру атомарного пакета. Все существующие CSV остаются допустимыми.

Новые действия:

- `batch_begin` / `batch_end`: мышиные события внутри публикуются под одним
  lock. Весь пакет имеет одно время; вложенные пакеты, ожидания, fixtures,
  controller и смена режима внутри запрещены. Лимит — 256 событий.
- `wheel_half_up` / `wheel_half_down`: по 60 единиц для проверки дробного колеса.
- `wait_shop`, `wait_almanac`, `wait_chooser`, `wait_challenge`: ожидание
  соответствующего верхнего экрана. Они не гарантируют завершения всех анимаций.
- `wait_idle`: очередь и удерживаемые жесты закончены. Это ожидание ввода,
  а не окончания игровой анимации.

Журнал `PvZ mouse event` записывает обработку на guest thread: ID, поколение,
вид события, координаты, кнопку, колесо и причину отмены. Журнал публикации
реплея отдельно не считается подтверждением игрового действия.

## Проверки и повторные прогоны

CTest включает тесты транспорта (32 способа разбиения потока на кадры),
отмены/переполнения, колеса, времени жизни widget tree, парсера всех CSV
и устаревания отчёта. Проверки manifest используют временные файлы.

Нативный сценарий `tests/replays/mouse_transport.csv` проверяет atomic Up/Move,
восстановление кнопки после ухода на фон и focus loss, смену PC/Console,
игнорирование orphan releases и дробное колесо. Анализатор:

```powershell
python scripts/check_mouse_transport.py <log>
```

Два независимых повтора пяти сценариев игровых состояний:

```powershell
./scripts/run_input_audit.ps1 -Repeats 2 -GameDataRoot runtime-data/edition-test/assets
python scripts/check_input_coverage.py
python scripts/input_audit_manifest.py --verify runtime-data/input-coverage-validation.json
```

Каждый запуск получает отдельную копию одного неизменяемого baseline профиля.
По умолчанию это подготовленный `runtime-data/input-audit-test-user`:
в нём открыты Zen Garden, Shop и Almanac. Профиль только мини-игр для этих
сценариев не подходит. Другой подготовленный профиль можно передать через
`-BaselineUserRoot`; оригинал не изменяется.
Сервисные сценарии требуют проверенного Full-импорта; `-GameDataRoot` указывает
его каталог (в этом workspace — `runtime-data/edition-test/assets`). Скрипт
проверяет редакцию по нативному журналу и останавливает прогон на Trial.
Отчёт содержит хеши EXE, исходников, тестов, audit scripts, всех повторов логов,
реплеев и baseline. Любое несовпадение делает отчёт устаревшим.
RNG игры не фиксируется; `rng_seed=null` в отчёте сообщает это явно.

Численные результаты финальной проверки записываются в
`runtime-data/input-coverage-validation.json` и
`runtime-data/mouse-transport-validation.json`.

На сборке от 9 октября CTest прошёл **9/9**. Два независимых повтора
пяти игровых сценариев дали **54/54**: исходные 27 критериев проверены
в каждом повторе. Все десять запусков завершили отведённое время без падений;
проверка хешей отчёта прошла. Первые прогоны в Trial выявили неподходящие
условия тестирования и не включены в успешный итоговый отчёт.

Отдельная серия транспорта и жестов прошла **54/54**: два запуска
`mouse_transport.csv`, 9 критериев переноса конвейерной карточки, 5 критериев
PC/Console-лопаты, 12 критериев Heavy Weapon, завершение реплеев и отсутствие
падений. Для Heavy Weapon используется копия без `game_20.dat`, чтобы штатный
ContinueDialog не возобновлял партию с уже купленным оружием. Урок лопаты
проверен на новом профиле с `fixture_level=5`; завершённый Adventure этот
урок не запускает. Подготовленные профили и их хеши записаны в отчёте,
неподходящие первоначальные попытки сохранены отдельно в `attempts`.

Оба отчёта прошли `scripts/input_audit_manifest.py --verify` после последнего
прогона. Физический геймпад этой серией не проверен.

Известные отдельные задачи из аудита — Cob Cannon, Last Stand и полный обход
service/VS экранов — остаются в manual list. Эти изменения исправляют основу
мышиного ввода и не заявляют завершение всех игровых маршрутов.
