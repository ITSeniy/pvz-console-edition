# PS Vita Touch и мышь Xbox-порта

Исследование локального `PSVita Image/eboot.bin`, 7 октября 2026. Восстановлена цепочка от опроса сенсорных панелей до выбора карточки, посадки и лопаты. Наиболее полезная находка для порта — разделение выбора при нажатии и попытки посадки при отпускании. Эта схема позволяет перетащить карточку на поле и использует обычные игровые проверки.

Сопоставление выполнено с текущим `src/mouse_bridge.cpp`. Код игрового ввода и исходные образы в рамках исследования не изменялись. Vita не запускалась: ниже результаты статического разбора, а не наблюдение поведения в эмуляторе. Названия методов без символов являются смысловыми обозначениями; точные адреса и инструкции сохранены отдельно.

## Основание и воспроизведение

SELF содержит открытые ARM/Thumb-сегменты. SHA-256 оригинального EBOOT: `1dd200eb9ad31826ace7844f11a5aead003bf57d83aaaccb3a7bc3ab49414afd`. Сегменты: `0x81000000`, размер `0x44AEBC`, и `0x8144B000`, размер `0x139820`.

Module info `PvZPSP` находится по `0x813AB780`. Таблица `.ARM.exidx` занимает `0x813AE964..0x813C77A4`: 12 744 записи, последняя является границей перед module info. Получено 12 743 ограниченных диапазона кода с учётом Thumb-бита. Это существенно надёжнее чтения фиксированного числа байтов после каждого указателя vtable, но не заменяет полную таблицу символов: несколько внутренних входов могут принадлежать одному диапазону unwind.

```powershell
python scripts/analyze_vita_touch.py
```

Нужны сегменты от `scripts/analyze_cross_platform.py` и уже установленный Capstone в `tools/python`. Скрипт проверяет SHA-256, порядок EXIDX, точные слоты Touch-vtable, импорты SceTouch и ключевые прямые вызовы. Результаты: `research/cross-platform/vita-touch/`.

| Файл | Содержимое |
|---|---|
| `metadata.json` | Идентичность образа, диапазоны EXIDX, ограничения |
| `vtables.json` | 15 первичных таблиц с адресами, слотами и размерами диапазонов |
| `imports.json` | 36 библиотек импорта; NID и адрес каждой функции |
| `functions.txt` | 902 диапазона: Touch, аппаратный ввод, Board и непосредственные помощники |
| `function-index.json` | Полный индекс диапазонов и смысловые метки |
| `verified-evidence.json` | Проверенные вызовы, синтетическая кнопка и политика именования |
| `direct-edges.json` | 67 644 кандидата прямых переходов/вызовов |
| `decode-coverage.json` | Число декодированных байтов в каждом диапазоне |

Линейный дизассемблер может прочитать literal pool как инструкции или остановиться на данных. Количество декодированных байтов не доказывает правильность всех инструкций. Косвенные вызовы vtable проверялись вручную: их нет в полном виде в `direct-edges.json`. Сходство мнемоник Android/Vita не используется как доказательство имени метода.

## Аппаратный ввод: две панели, один основной контакт на каждой

Импорты определены по NID, а не по приблизительному сходству кода:

| NID | Импорт | Stub в Vita |
|---|---|---|
| `0x10A2CA25` | `sceTouchGetPanelInfo` | `0x813AA620` |
| `0x1B9C5D14` | `sceTouchSetSamplingState` | `0x813AA630` |
| `0xFF082DF0` | `sceTouchPeek` | `0x813AA640` |

Инициализация `0x810D92C2` читает геометрию портов 0 и 1, затем включает sampling обоих. Опрос `0x810D94F6` вызывает `sceTouchPeek(port, buffer, 1)` для каждой панели. Контакты отслеживаются по ID функцией `0x810D8BD8`; отдельные списки соответствуют новым, удерживаемым, перемещённым и завершённым контактам. Tracker задаёт порог перемещения 10 в сырых координатах панели. Переносить его в мышь как 10 экранных пикселей нельзя.

Преобразователь `0x810D903A` обслуживает массивы по восемь записей на панель и нормализует координаты. Dispatcher `0x810D8F62` переводит внутренние состояния 1/2/3/0 в события 4/5/6/7: начало, удержание, движение, конец. Восемь записей — ёмкость программного массива, а не доказательство восьми одновременных игровых курсоров или аппаратного лимита.

Регистрация `0x810D54D6` подписывает игровой мост на **контакт с индексом 0** передней панели (`0x810D52AC`) и индекс 0 задней (`0x810D5446`). Передний callback записывает координаты, дельты, длительность, force и признаки pressed/held/ended в блок `0x814EBB50`. Задний callback записывает только pressed/held/ended и длительность; координаты в этот игровой блок не передаёт.

| Поле глобального блока | Значение по callback |
|---|---|
| `+0x00/+0x04` | Передние координаты после масштабирования к renderer |
| `+0x08/+0x0C` | Передние координаты для последующего преобразования области |
| `+0x10/+0x14` | Дельты движения переднего контакта |
| `+0x18/+0x1C` | Удержание передней / задней панели |
| `+0x20/+0x24` | Начало контакта передней / задней панели |
| `+0x28/+0x2C` | Завершение контакта передней / задней панели |
| `+0x30/+0x34` | Длительность переднего / заднего контакта |
| `+0x44` | Признак движения переднего контакта |

`0x8104B4C8` преобразует передние координаты к логическому viewport и затем через WidgetManager, сохраняет их в `LawnApp+0x708/+0x70C` и генерирует framework Down/Drag/Up по изменениям состояния. `0x8104BC3C` также выполняет преобразование координат. Значения масштабирования не следует брать из физического разрешения Vita-атласов.

В `Board::Draw`, `0x810F777E`, найдена отдельная проверка rear pressed (`+0x24`, инструкция `0x810F77D2`). При разрешённом touch-маршруте, дополнительном Board-флаге и режиме 24 либо режиме 44 с дополнительным состоянием она вызывает метод LawnApp через vtable `+0xDC` с ресурсом из `0x81502654`. Точное назначение ресурса/метода здесь не восстановлено. Эта ветка подтверждает отдельное использование заднего нажатия, но **не доказывает сбор солнца задней панелью**. Полный перечень rear-действий остаётся открытым.

Форматы и NID сверены с первичными описаниями [VitaSDK SceTouch](https://raw.githubusercontent.com/vitasdk/vita-headers/master/db/360/SceTouch.yml), [touch.h](https://raw.githubusercontent.com/vitasdk/vita-headers/master/include/psp2/touch.h) и [структурами module info/imports](https://raw.githubusercontent.com/vitasdk/vita-toolchain/master/src/sce-elf-defs.h). Из этих источников берутся названия API и формат, игровые действия установлены по локальному EBOOT.

## Как касание доходит до GamepadControlsTouch

В Vita тач проходит через framework мыши, после чего Board переводит его в специальную игровую кнопку **20 (`0x14`)**. Это не Xbox A, у которого наш мост использует код 6.

```text
sceTouchPeek → tracker контактов → callback передней панели
    → логические координаты LawnApp → WidgetManager Down / Drag / Up
    → Board mouse handlers → GameButtonDown/Up(20, player 0)
    → GamepadControlsTouch.OnButtonDown / OnButtonUp
```

| Этап | Адрес | Подтверждение |
|---|---|---|
| Board MouseMove / MouseDrag | `0x810F0B0E` / `0x810F0B40` | Framework + виртуальный метод копирования координат |
| Board MouseDown | `0x810F0B72` | Framework + Board vtable `+0xFC` |
| Board MouseUp | `0x810F0B94` | Framework, Challenge, затем Board vtable `+0x104` при разрешённом маршруте |
| Touch Down adapter | `0x810FD2CC` | Вызывает Board vtable `+0xC4` с кнопкой 20 |
| Координаты | `0x810FD2DE` | App `+0x708/+0x70C` → controls `+0x70/+0x74` |
| Touch Up adapter | `0x810FD304` | Вызывает Board vtable `+0xC8` с кнопкой 20, затем обнуляет controls XY |
| Board GameButtonDown / Up | `0x810FCD4C` / `0x810FCF7E` | Выбирают controls по индексу gamepad и вызывают слоты 0/1 |

Порядок в Up adapter существенен: сначала игровая обработка отпускания использует последнюю позицию, **после** неё координаты controls сбрасываются. В нашем мосте аналогом должны быть координаты самого события release, а не позднее состояние глобального указателя.

Маршрут mouse→touch включён при нулевом байте `LawnApp+0x3AD`. В обработке ввода ненулевое значение подавляет передние touch-флаги. Смысл соответствует переключению маршрута управления, но оригинальное имя поля не известно. У MouseUp также есть Board-флаг и возможность потребления события Challenge.

## Vtable: Android нельзя использовать как готовую разметку Vita

Первичная `GamepadControls` расположена в `0x81443CB4`, `GamepadControlsTouch` — в `0x814491B8`. В Android virtual KeyDown/KeyUp присутствуют в другой раскладке; в Vita после Axis идут Update и графические методы, а DrawFrame входит в vtable. Touch дополнительно вставляет предикат области поля перед методами состояний.

| Смысл метода | Vita обычный: слот / адрес | Vita Touch: слот / адрес |
|---|---|---|
| OnButtonDown | 0 / `0x811219F8` | 0 / `0x811C179A` |
| OnButtonUp | 1 / `0x811228EC` | 1 / `0x811C2ADA` |
| OnGameAxisMove | 2 / `0x8112294C` | 2 / `0x811C2E4C` |
| Update(float) | 3 / `0x81122F3C` | 3 / `0x811C343C` |
| BeginDraw | 4 / `0x81123A32` | 4 / `0x811C40DC` |
| Draw | 5 / `0x81124EEC` | 5 / `0x811C55BC` |
| EndDraw | 6 / `0x811256AA` | 6 / `0x811C5EFC` |
| DrawFrame | 8 / `0x81120020` | 8 / `0x811BFE0A` |
| Проверка области touch | — | 9 / `0x811C6350` |
| EnterState / ExitState | 9 / 10 | 10 / 11 |
| UpdateStates | 11 / `0x811257DA` | 12 / `0x811C602C` |
| GotoState | 12 / `0x81120E16` | 13 / `0x811C0C60` |
| GetSnapToGridPos / XY | 13 / 14 | 14 / 15 |
| Деструкторы | 15 / 16 | 16 / 17 |
| PickupUsableSeedPacket | 17 / `0x811258F6` | 18 / `0x811C6148` |

Последний метод подтверждён по чтению Coin seed/ID и записи CursorObject type 2. Он **не является GetSeedBank**. Предикат слота 9 берёт текущие App XY, переводит float в int и проверяет включённые границы `0 ≤ x ≤ 800`, `80 ≤ y ≤ 590`. Это область допуска к действию, а не окончательная проверка клетки: дальше идут native PixelToGrid и CanPlantAt.

## Карточка, посадка и отпускание

Touch Down `0x811C179A` сначала проверяет игрока и передаёт кнопку Challenge. Для кнопки 20 использует native Board hit-test `0x810F9468`. Касание карточки вызывает помощник выбора `0x811C1512`; hit type 4 связывается с конкретным SeedPacket, после чего `0x8118A538` проверяет возможность взять карточку. При отказе в этой ветке выбор очищается. При повторном выборе уже выбранного индекса также есть переход в очистку; в нашем ПК-мосте такой явный toggle отсутствует.

Выбранный индекс Vita находится в controls `+0xC0`, отсутствие обычной карточки обозначено значением **10**. SeedBank packets начинаются с `+0x48`, stride `0x74`. Начало выделения сбрасывает native animation counter. При уже удерживаемом dropped seed (CursorObject type 2) обычный выбор карточки прекращается. Есть и коррекция попадания возле верхней границы: для `y < 20` повторяется hit-test с `y+20`, а при попадании в карточку Y устанавливается в 20. Это конкретная адаптация сенсорной зоны, которую мыши автоматически повторять не требуется.

Обычная попытка посадки находится в **Touch Up `0x811C2ADA`**, а не в touch-ветке Down. После проверок потреблённого события, области поля и Board-состояния она повторно вызывает CanPickUp, вычисляет клетку с учётом типа растения и проверяет CanPlantAt `0x810F064C` (ноль означает успех). Для Имитатора используется реальный тип из отдельного поля. При допустимой клетке активируется выбранный пакет (`0x8118B142`), затем вызывается Board MouseDownWithPlant `0x810F9C94`.

После вызова Board MouseDownWithPlant выполняются ClearCursor и GotoState(1). Эти два шага есть и в ветке, где CanPickUp разрешил действие, но CanPlantAt отказал. Индекс `+0xC0` устанавливается в 10 только при признаке успешной активации пакета. Поэтому «при любой ошибке Vita полностью теряет выбор» было бы неверным выводом. Итоговую картинку после StateEnter следует проверять запуском.

На отпускании вне области поля посадка пропускается. Дополнительная очистка касается dropped-seed режимов и специального курсора типа 8; обычный выбранный индекс здесь не сбрасывается безусловно. Это позволяет отделить выбор карточки в верхней панели от последующего действия на газоне.

Практический результат: из кода следует возможность последовательности **карточка Down → движение на поле → Up с попыткой посадки**. Последовательность **тап карточки → отдельный тап поля** использует те же выбор и Up. Проверять обе в реальном Vita запуске ещё предстоит.

## Лопата, монеты и специальные режимы

Лопата: hit type 5 в Touch Down переключает CursorObject type 6/0, вызывает native PickUpTool и очищает выбор карточки. Само применение находится в Up, `0x811C2DAE..0x811C2DD4`: Board MouseDownWithTool `0x810FACD0`, ClearCursor, сброс дополнительного Board-поля. Это допускает перемещение удерживаемой лопаты до отпускания. В нашей ПК-мыши оба отдельных клика действуют на Down; консольная мышь использует Xbox B и native удержание примерно секунду.

В Vasebreaker и Slot Machine touch-ветки Down по coin hit type 3 вызывают Coin MouseDown `0x81113292`, устанавливают байт controls `+0x3C` и сохраняют исходную клетку в `+0xAC/+0xB0`. Up при выставленном байте очищает его и завершает обработку: тот же тап не должен тут же посадить полученный пакет. BaseTouch Update `0x811BFC9E` может снять этот флаг после перемещения в другую клетку в этих режимах. Следовательно, это контекстный барьер повторного действия, а не запрет любого release после любого сбора монеты.

Метод PickupUsableSeedPacket `0x811C6148` записывает в CursorObject type 2, тип семени и ID исходного Coin; предыдущий удерживаемый пакет обновляется через отдельный native helper. Это подтверждает необходимость отдельного состояния dropped seed, которое уже есть у нас (`selection.usable_seed`). Полная цепочка сбора обычного солнца передним тачем в данном исследовании не восстановлена, и её нельзя выводить из только что описанного Vasebreaker-барьера.

Рядом с Touch-классами есть сбор через **датчик движения**, `0x811BF960`, вызываемый Touch Update. Импорты `sceMotionStartSampling` и `sceMotionGetState`, а также чтение `SceMotionState` отделяют его от rear touch. Ветвления сравнивают компонент угловой скорости с порогами ±0.5 и используют ограничение повторения 0.75. Это отдельная платформенная возможность; переносить её как поведение мыши оснований нет. Названия API и layout сверяются с [SceDriverUser NID](https://raw.githubusercontent.com/vitasdk/vita-headers/master/db/360/SceDriverUser.yml) и [motion.h](https://raw.githubusercontent.com/vitasdk/vita-headers/master/include/psp2/motion.h).

На conveyor после успешной активации есть явная коррекция индексов: выбранный индекс уменьшается при необходимости, а выбор другого активного игрока сдвигается, если удалённая карточка находилась перед ним. Ветка `0x811C2CCA..0x811C2D3A`, с отдельными условиями режимов 83/88. В нашем мосте native Xbox также может менять банк; наличие этих веток Vita само по себе не доказывает ошибку Xbox. Для будущего drag важно не считать прежний числовой индекс устойчивым ID карточки.

Beghouled / Beghouled Twist вызывают Challenge-обработчики, а карточки используются как покупки улучшений. Zombiquarium тоже имеет отдельную покупку. Heavy Weapon обрабатывается особо даже в помощнике выбора, а общий Touch Draw пропускает этот режим и Twist. Общую посадку при release нельзя навешивать на все карточки мини-игр.

У TreeOfWisdomControlsTouch и ZenGardenControlsTouch собственные Down и Up. Tree Up `0x811C689C` делает hit-test и применяет инструмент для hit type 19 при разрешении Challenge. Zen Up `0x811C7360` проверяет hit относительно сохранённого типа, обрабатывает особый hit 25, затем вызывает собственный Down с кнопкой 6 либо 9. Значит, часть touch-up поведения построена на существующих игровых командах даже в Vita; при будущем расширении мыши нужно исследовать конкретные native Xbox Zen/Tree-методы, а не копировать общий обработчик посадки.

## Сравнение с текущей мышью

| Действие | Vita Touch | Наш ПК-режим | Наш консольный режим / вывод |
|---|---|---|---|
| Выбор обычной карточки | Down, native CanPickUp; повтор выбранной может очистить выбор | Down, CanPickUp; индекс и анимация сохраняются | Down сохраняет выбор даже пока карточка недоступна |
| Посадка | Попытка на Up в конечной точке | Попытка на Down следующего клика по полю | Native Xbox A Down/Up; семантика Xbox |
| Drag карточки на поле | Цепочка Down→XY→Up даёт попытку посадки | Обычный Up не сажает | Самый полезный кандидат расширения ПК-режима |
| Недопустимая клетка | CanPlantAt; ClearCursor/State(1), индекс очищается только по успешной ветке | Native A; выбор остаётся, если use counter не изменился | Это различие UX, не установленная ошибка |
| Лопата | Выбор Down, применение Up | Выбор Down, применение следующим Down | B с native удержанием; перенос release требует отдельной схемы |
| Сбор монеты / dropped seed | Доказан специальный барьер Down→Up в Vasebreaker/Slot | Discrete CoinCollect на Down и `continue`; отдельное usable_seed | Нельзя дополнительно запускать Board held collector тем же событием |
| Лента | Коррекция индексов после native действия | Мост хранит индекс, очищает по изменению использования | Для drag нужна проверка актуальности карточки/банка |
| Beghouled, Twist, Quarium | Отдельные Challenge/purchase ветки | Такие ветки уже выделены | Release посадки должен обходить их |
| Потеря фокуса, смена экрана/ввода | Подавление touch-флагов и framework routing | Есть отмена capture, выбора, состояния мини-игр | Использовать существующую отмену и для нового жеста |

Точки в текущем исходнике: [выбор и действия ПК-мыши](../src/mouse_bridge.cpp#L1037), [карточки/обычная посадка](../src/mouse_bridge.cpp#L1093), [консольная лопата и native кнопки](../src/mouse_bridge.cpp#L1190), [координаты controls](../src/mouse_bridge.cpp#L1235), [отмена захвата](../src/mouse_bridge.cpp#L710). Номера относятся к текущему файлу на дату исследования.

Для Xbox уже имеются native MouseHitTest `0x82139238`, CanPickUp `0x8220F370`, Board GameButtonDown/Up `0x8214CDC0/0x8214D1B8`, PickUpTool `0x82139808`, MouseDownWithTool `0x821388A0`, ClearCursor `0x82139AC0`. Поведение release можно собрать вокруг этих команд. **Отправка кнопки 20 в Xbox не добавит Vita Touch:** соответствующих классов в этой сборке не найдено.

Нельзя переносить layout объектов. Примеры: Vita selected index `+0xC0`, Xbox `+0xBC`; Vita cursor XY controls `+0x70/+0x74`, Xbox `+0x74/+0x78`; Vita packet stride `0x74`, Xbox `0x7C`; разная раскладка vtable и endian. Переносится последовательность действий и проверок, каждое Xbox-поле подтверждается отдельно.

## Конкретный следующий шаг реализации

Дополнение 8 октября: перенос карточек и лопаты, повторный клик для снятия
выбора и проверки отмены реализованы в Xbox-мосте. Описание текущего
управления — [item-drag.md](item-drag.md). Сравнение выше фиксирует состояние
порта на дату самого исследования, 7 октября.

Первый кандидат — **перетаскивание обычной карточки в ПК-режиме**, с сохранением существующей посадки отдельным кликом. При Down на доступной обычной карточке сохранять Board, controls, банк, данные выбранного пакета и начальную точку. При движении обновлять preview существующим ApplyPointer. При Up на газоне сверять живой экран, владельца ввода и актуальность выбора, применить точку самого события и один раз вызвать существующее native Xbox действие посадки.

Release после простого клика карточки должен оставить выбор; release после клика поля, уже обработанного на Down, не должен сажать второй раз. Начало на монете, UI, покупаемом улучшении либо в отдельном игровом режиме не создаёт жест посадки. Допустимый порог движения следует выбрать в логических координатах мыши, а не из Vita raw threshold.

Жест должен отменяться при потере фокуса, открытии modal, смене Board/банка/режима управления и выходе указателя из допустимой области. Исчезновение или сдвиг conveyor-карточки требует отмены либо доказанной повторной идентификации; одного прежнего индекса недостаточно. Эти условия дополняют уже существующую отмену в DispatchWidgets, а не заменяют её.

Отдельным следующим изменением можно сделать drag лопаты с действием на Up; console B hold нужно рассматривать самостоятельно. Zen/Tree и остальные специальные курсоры требуют собственных native маршрутов. Vita даёт полезные образцы, но не единый обработчик для всех действий.

Проверка будущей реализации должна включать: click-card/click-field, drag-card/release-field, release над панелью/за полем, недоступную карточку, отказ клетки, Имитатора, dropped seed, изменение ленты во время жеста, быстрое Down+Up между кадрами, modal/смену владельца ввода и покупки мини-игр. В этом исследовании игровые smoke-тесты порта не повторялись: изменений runtime нет.
