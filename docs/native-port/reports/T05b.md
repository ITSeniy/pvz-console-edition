# T05b — детерминированный диагностический replay

## 1. Итог

В отдельном worktree добавлены seed override, запись фактических шагов доставки
seconds replay, конвертер и синхронная доставка по app logical step. Дополнительно
изолированы две зависимости от порядка render/logic: дробное обновление и первая
отрисовка Board перед размещением preview zombies. Это диагностический режим
под флагом; обычные CSV, системные часы и проверки регрессий не изменены.

Adventure (5000), Versus (6000), Heavy Weapon (3000) и меню (5000) дали
побайтно одинаковые пары; Zen имеет 323 различающихся кадра, причина пока
не найдена. Проверка +1 sun сработала ровно на кадре 1800.
Обычные регрессии: Services 78/79, Feedback 60/61, Multiplayer 66/66,
Shop 70/70. Из-за двух отказов T05b не объявляется полностью готовой к приёмке.

## 2. Изменённые файлы

- `src/deterministic_replay.cpp` — новые флаги и узкие Xbox hooks; необязательная
  трасса глобального MT для поиска источника расхождений.
- `CMakeLists.txt` — одна строка регистрации нового TU поверх исходного состояния T05.
- `src/input_replay.cpp` — запись шагов только под record flag, отдельный синхронный

- `docs/native-port/state-dumps.md` — дополнение T05b с командами и ограничениями.
- `docs/native-port/reports/T05b.md` — этот отчёт.

Все команды — из указанного worktree, игровые процессы последовательно.
Полный самостоятельный пример record→convert→две новые копии профиля→compare
приведён в `docs/native-port/state-dumps.md`, раздел T05b. Для повторения таблицы
меняются только следующие параметры этого примера:

| Сценарий | Исходный CSV в tests/replays | Секунды | Число state frames | Начальный профиль | Cursor |
|---|---|---:|---:|---|---|
| Adventure | adventure_mouse.csv | 70 | 5000 | новый, только build/pc_defaults.toml | pc |
| Versus | feedback_vs_two_pads.csv | 80 | 6000 | копия zen-shop-probe-user | pc |
| Мини-игра | feedback_heavy_console.csv | 52 | 3000 | копия zen-shop-probe-user | console |
| Zen | services_zen_regression.csv | 64 | 5000 | копия zen-shop-probe-user | pc |
| Меню | services_menus_regression.csv | 64 | 5000 | копия zen-shop-probe-user | pc |

Во всех процессах seed=42, vsync=false, pause_on_focus_loss=false,
mouse_cursor/input_trace/test_unlock/replay_controller=true. Сначала один
seconds-record, затем два frame-locked запуска одного созданного steps.csv.
Для пары используется один неизменный входной манифест, переданный через
`pvz_state_inputs_sha256`. State dump остаётся в прежней фазе after-root-update.

Локальный исследовательский runner и аудит сохранены в игнорируемом runtime-data:

Runner проверяет JSONL существующим неизменным компаратором. Независимый аудит
проверяет ожидаемую длину, mode=0/76/20/44 в scene=3, smoke/GPU/fatal, отсутствие
ошибок frame replay и его завершение; сырые SHA двух dump сравниваются отдельно.
Для поздних запусков дополнительно сохранён launch-inputs.json каждого процесса,
сопоставленный с общим манифестом. Первые пары используют общий манифест и
проверенные команды копирования профиля, без ретроспективного «launch snapshot».

## 4. Результаты

### Метод и адреса — проверено по Xbox

- `824943A0` получает decimal u32 в r3 и вызывает прежний seed original.
  `KeTimeStampBundle` не меняется. Пустая строка отключает override, 0 допустим.
- `8247FFC0`, ветка app+5A7==0, вызывает `824A6140` и корневой WidgetManager;
  события публикуются перед этим update. Нумерация replay начинается с загрузки,
  нумерация state.frame — с первого записываемого MainMenu/Board. Это разные оси.
- `824752F0` передаёт fractional f1 в manager `824A6198`. Под новым флагом
  wall-time вызовы заменены одним original с f1=1.0 после каждого app logic.
  Используется отдельная копия PPCContext/stack area; ABI контекста вызывающего
  хука сохраняется. Логическая единица — шаг сетки 100 Гц, не host Present.
- `8217C7D8..E0` в CutScene::Update ждёт первой отрисовки Board+560C.
  После этого выполняются preload `821788A8` и preview `82179590`.
  Board::Draw `82146A60` записывает поле по `82146B74/94`.
  Caller `82478108` под frame-locked возвращает штатное false до реального
  первого Draw существующей Board; счётчик не подделывается. LawnApp virtual
  Update вызывается по `82478220..30`, его существующий hook не заменён.

### Неуспешный первый вариант v1 — не скрыт

Только seed и доставка по шагам не дали детерминизма Heavy Weapon. Первая
разница — **frame=314, zombies.count: 11 против 0**; также rng_index=388/279.
Всего различались **1304** кадра. В двух трассах MT кластер из **109** вызовов
размещался на app step 752/753. Через сохранённый LR bounded-wrapper установлены
`82178100` и PlaceStreetZombies `82179590`, затем проверен draw gate в CutScene.
Наблюдавшиеся global MT вызовы шли на одном host thread; гипотеза «обязательно
фоновый RNG» не подтвердилась. Это не доказательство отсутствия иных потоков
во всей игре. Трассы и disassembly находятся в runtime-data/research.

## 6. Не проверено и риски

Диагностическая нормализация меняет порядок fractional/logic и задерживает app
update перед первым Draw. Это инструмент сравнения двух реализаций **в одинаковом
диагностическом режиме**, не доказательство эквивалентности обычной игре.
Зависимость первой отрисовки исключает headless-прогон без настоящего renderer.
Нет обещания детерминизма любого seed, полного прохождения, любого FPS/нагрузки,
локальных RNG, UI repeat, физического ввода и всех фоновых потоков.

Снимки остаются ограниченной проекцией T05, без полной анимации/UI и всех таймеров.
Не добавлялись допуски float, пропуск RNG, перенумерация/сдвиг кадров и исключение
неудобных полей. Неполный/повреждённый JSONL отклоняется прежним компаратором.

Seconds-record может попасть на соседний шаг из-за планировщика; новое расписание
фиксирует один конкретный записанный прогон. Это не восстановление единственной
«идеальной» интерпретации старого CSV. Frame replay readiness error прекращает
доставку и пишет ERROR, но не убивает игру; результат проверять вместе с журналом.
Необязательная RNG trace очень медленная и не включена в итоговые пары.
