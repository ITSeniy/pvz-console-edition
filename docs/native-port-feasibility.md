# Переход со статической рекомпиляции на нативный порт: оценка

Исследование 16 октября 2026. Вопрос: можно ли сменить профиль проекта с рекомпиляции
`default.xex` через ReXGlue на нативный исходный код. Цели: облегчить разработку и
исправление известных проблем. Код порта не менялся. Числа ниже получены по локальным
файлам проекта: `.cache/pvz-image.bin`, `generated/`,
`research/cross-platform/android-symbols.json` и `research/pvz-pc`. Внешние проекты
проверены по их репозиториям на GitHub.

## Короткий ответ

Переход возможен, но не одним шагом. Переписывать игру заново по PC-декомпиляции
означает надолго потерять играбельную 0.7.0. Консольная ветка заметно отличается от PC.
Рекомендуется **гибридный путь «декомпиляция внутри рекомпиляции»**: функции игры по
одной заменяются нативным C++, рекомпилированный код остаётся страховкой. Когда
нативного кода станет достаточно, ReXGlue можно убрать. Так уже работает мод PvZ TV
Touch для Android TV (см. ниже). Его исходники и символы Android TV покрывают почти всю
консольную часть, которой нет в PC-декомпиляции.

## Что есть сейчас

| Объект | Объём |
|---|---:|
| Рекомпилированный Xbox-код (`generated/default`) | 20 999 функций, 122 МБ C++ (вместе с CRT, XDK, FEAST, Sexy) |
| Код порта (`src/`) | ~11 400 строк; 128 `REX_HOOK_RAW`, 227 уникальных guest-адресов |
| Классы с RTTI в образе Xbox | 195 |
| Именованные функции Android TV `libGameMain.so` | 13 002 (368 vtable) |
| PC-декомпиляция `research/pvz-pc` (1.0.0.1051) | 141 `.cpp`, ~303 000 строк `.cpp`/`.h` |

Сейчас каждое исправление пишется как хук на безымянный адрес `sub_82xxxxxx`. Данные
игры читаются по смещениям из guest-памяти (big endian). Поэтому проблемы рендера
(Zombiquarium), частоты кадров и ввода приходится искать сквозь эмуляцию Xenos GPU и
сгенерированный код без имён.

## Покрытие консольного кода внешними источниками

Классы Xbox из RTTI сопоставлены по имени с классами PC-декомпиляции и Android TV
(символы функций, `vtable for`, `typeinfo for`):

| Есть в PC | Есть в Android TV | Классов | Что это |
|:---:|:---:|---:|---|
| да | да | 83 | Игровое ядро: Board, Plant, Zombie, Challenge, SeedPacket, LawnApp, частицы, анимации, виджеты Sexy |
| нет | да | 48 | **Консольная часть:** `GamepadControls`, `BaseGamepadControls`, `ZenGardenControls`, `TreeOfWisdomControls`, `VSSetupMenu`, `VSResultsMenu`, `MainMenu`, `HouseChooserDialog`, `MailScreen`, `HelpBarWidget`, `LawnMenuParser`/`MenuWidget`, `SettingsDialog`, `WaitForSecondPlayerDialog`, `TrashBin`, профили игроков и др. |
| нет | нет | 13 | Xbox LIVE и хранилище: `LeaderboardMenu`, `HouseMenu`, `InternetManager`, `StorageFileOperation`, `IQNetCallbacks`, `BigInt`… |
| да | нет | 10 | Платформенные бэкенды PC: DirectDraw/D3D7, FMOD, `PakInterface`, `HTTPTransfer` |

Вывод: **всё, без чего консольную игру нельзя собрать нативно, имеет имя хотя бы в
одном источнике.** Без аналога остаются только функции LIVE. Порт и так их не
поддерживает.

Совпадение имени класса не означает одинаковый код. В общих классах (Board, Challenge,
Zombie) консольная ветка добавила второго игрока, Versus и геймпады. Смещения полей
Android и Xbox различаются: Controls `+6C/+70` против `+74/+78`, SeedBank в Board
`+20C` против `+1A4`. См. [cross-platform-research.md](cross-platform-research.md).
Правило ведения: **Android TV — для имён и структуры алгоритма, PC — для читаемого
исходника, Xbox — единственный источник истины для поведения и смещений.**

## Существующие проекты

### Android TV: PvZ TV Touch (ZombieYetis)

[ZombieYetis/PlantsVsZombies-AndroidTV](https://github.com/ZombieYetis/PlantsVsZombies-AndroidTV),
GPL-3.0, обновлялся в октябре 2026. Это не полная декомпиляция, а мод поверх
оригинального `libGameMain.so`. Хуки (Substrate) заменяют функции, а
`old_<Класс>_<Метод>` вызывает оригинал. За 1488 коммитов значительная часть игры
переписана как C++ в исходной структуре классов, около 5 МБ `.cpp`/`.h`:

- `Zombie.cpp` 450 КБ, `Board.cpp` 420 КБ, `Plant.cpp` 190 КБ, `SeedChooserScreen.cpp` 230 КБ;
- консольные классы: `GamepadControls.cpp` 75 КБ, `VSSetupMenu.cpp` 68 КБ,
  `VSResultsMenu.cpp`, `MainMenu.cpp`, `HelpBarWidget`, `HouseChooserDialog`, `MailScreen`;
- заголовки с раскладкой полей почти всех классов консольной ветки (`PvZ/Lawn/**.h`);
- `Symbols.cpp`: таблица имён → адресов `libGameMain.so`;
- новые возможности поверх консольной ветки: сетевая игра (`NetPlay.h`,
  `NetplayLobbyWidget`), Zombatar, повторы, достижения, таблицы рекордов, ИИ для Versus.

Это **ровно та модель, которая рекомендуется здесь**, и рабочее доказательство, что её
можно довести до большого покрытия. Для нас проект ценен как справочник имён, полей и
алгоритмов консольных классов. Пункты дорожной карты «Online play» и «Zombatar» в нём
уже реализованы для той же консольной ветки.

Ограничение: **копирование кода из GPL-3.0 делает порт производной работой под GPL-3.0.**
У репозитория нет файла LICENSE, поэтому вопрос нужно решить до заимствований. Заголовки
с раскладкой структур — ближе к фактам, но и их лучше переписывать по Xbox, а не копировать.

#### Наша копия Android TV совпадает с целевой сборкой мода

`Chinese Android TV Image` — оригинальный, неизменённый APK. Пакет `com.trans.pvz`,
подпись Transmension `APK_TRAN`, версия `TM.15.12.24.1_0_0-…xiaomi`. Все 1681 файл
совпадают с SHA-1 подписанного `META-INF/MANIFEST.MF`, лишних файлов нет.
`libGameMain.so`: SHA-256 `ba4ebae0…edffbb4ef`.

Это **версия 1.1.5**, одна из двух, которые поддерживает PvZ TV Touch. Константы мода
для `PVZ_VERSION == 115` (`MagicNumbers.h`) совпадают с нашей библиотекой точно:
`Board::Update` по `0x164A88`, `Zombie::IsTangleKelpTarget` по `0x1AAD98`. Из 2170
mangled-имён, которые мод ищет через `dlsym` (`Symbols.cpp`), в нашей библиотеке есть
2163. Не хватает только 7 функций `Native::*` — они относятся к обвязке самого мода.
Значит, его заголовки, смещения полей и разобранные функции относятся ровно к нашему
бинарнику. Их можно проверять против `libGameMain.so` без поправок на версию.

В этой сборке есть консольные режимы: `LawnApp::IsCoopMode`,
`MainMenu::StartCoopAdventureMode`, `LawnApp::IsTwoPlayerGame`, 33 функции
`VSSetupMenu`, Heavy Weapon, `Mailbox`, остатки таблиц рекордов. Zombatar и сетевой игры
в оригинале нет — их добавил мод.

Для нативного порта важно и другое: **все 195 звуков Xbox (`sounds/*.xma`) лежат в
Android TV как обычные WAV с теми же именами.** Но это ухудшенные копии: все 195 — 22 050 Гц,
моно, 8 бит, а у Xbox 189 из 195 — 44 100 Гц и 153 стерео (T09, проверено 17.10.2026). Без
потери качества XMA-декодер нужен; WAV Android годятся только как запасной вариант. Музыка
Android — `day.ogg`, `crazydave.ogg` и финальная песня в `sounds/`; основную музыку всё
равно нужно брать с Xbox.

[SaMeiers/PvZ-TV-Anywhere](https://github.com/SaMeiers/PvZ-TV-Anywhere) — форк, который
запускает тот же ARM32 `libGameMain.so` на 64-битных Android и на ПК через ARM-раннер.
Это эмуляция, а не исходники; для нас интересен только как пример десктопной обвязки.

### Xbox 360

Исходной декомпиляции Xbox 360 PvZ не найдено. Нативных портов Xbox 360 игр с
восстановленным исходником нет вообще. Все известные проекты — статические рекомпиляции
на [XenonRecomp](https://github.com/hedge-dev/XenonRecomp) или ReXGlue (UnleashedRecomp,
MarathonRecomp и др.). Самые зрелые из них (UnleashedRecomp) растут именно гибридно:
много функций заменено нативным кодом поверх рекомпиляции.

## Варианты

### A. Полная замена: нативный порт на базе PC-декомпиляции

Взять PvZ-Portable или re-plants-vs-zombies и дописать консольную ветку по Android TV и Xbox.

- Плюсы: читаемый код, свой рендер (высокое разрешение, широкий экран), кросс-платформенность сразу.
- Минусы: дописать нужно 48 консольных классов и все консольные изменения общих классов.
  Пока это не сделано, Versus, Co-op, консольные мини-игры и меню не работают. Сохранения Xbox,
  XMA-звук (195 файлов `.xma`; FFmpeg декодирует XMA2; WAV Android TV — только 22 кГц моно 8 бит), PTX-текстуры и XCTD-пакеты нужно
  поддержать отдельно. Поведение будет расходиться с консольным, и проверить его можно
  только сравнением с рекомпиляцией.
- Оценка: большой проект с долгим периодом без играбельной версии. **Не рекомендуется как первый шаг.**

### B. Гибрид: функции заменяются по одной (рекомендуется)

Рекомпиляция остаётся базой, нативный C++ вытесняет её по подсистемам.

1. **Карта имён Xbox ↔ Android.** Дешёвый шаг с наибольшей отдачей. 195 RTTI-классов Xbox
   дают vtable. Слоты сопоставляются по порядку с 368 vtable Android, учитывая различия ABI:
   у Itanium два деструктора (D1/D0), у MSVC один scalar deleting destructor. Так все
   виртуальные методы получат имена. Невиртуальные функции именуются по графу вызовов от уже
   названных, строкам assert/ресурсов, константам и уже совпавшим таблицам (`gChallengeDefs`
   94/94). Результат — файл имён для ReXGlue и Ghidra: хуки и журналы начинают говорить
   `GamepadControls::OnButtonDown`, а не `sub_82…`.
2. **Типизированные структуры Xbox.** Заголовки с полями `be<T>` по образцу PC/Android, но
   со смещениями, проверенными на Xbox (`static_assert` на размеры). Это заменяет ручную
   арифметику смещений в `guest_layout.h`, `board_mapping.h` и т. п.
3. **Нативная замена подсистем, где живут проблемы.** Начать с ввода и меню
   (`GamepadControls`, `MenuWidget`, `LawnMenuWidget`): там открытые жалобы на двойные шаги
   паузы с геймпада и пропуски кликов в I, Zombie, а мышиный мост уже держит много хуков.
   Затем Heavy Weapon и мини-игры.
4. **Граница рендера.** Перехватить узкий API `Sexy::Graphics`/`D3DInterface` (DrawImage,
   FillRect, шрифты, состояния) и рисовать нативно, минуя эмуляцию Xenos. Отсюда
   исправление артефакта Zombiquarium, высокое разрешение и UI для широкого экрана. Этот слой
   можно взять из PvZ-Portable (LGPL-3.0, совместим при динамической линковке или открытом коде).
5. **Отказ от ReXGlue.** Когда нативная часть покроет игровой код, оставшееся — CRT, XDK,
   хранилище, XAM — заменяется платформенным слоем. После этого возможны Linux, macOS и мобильные
   платформы из дорожной карты.

Каждый шаг даёт пользу сам по себе и проверяется существующими реплеями (`smoke.ps1`,
`tests/`) против неизменённой рекомпиляции: можно сравнивать состояние доски кадр за кадром.

### C. Остаться на рекомпиляции, но с именами

Только шаги B.1–B.2. Минимальные затраты и заметное ускорение отладки, но без выигрыша
в рендере и платформах.

## Риски

- **Поведение.** Android TV — порт Transmension (пространство имён `TM`, сборка Xiaomi 2015)
  с собственными правками. PC-код — другая ветка. Любая нативная функция сверяется с Xbox,
  иначе появляются тонкие расхождения (тайминги, RNG, порядок обновления).
- **Endianness и 32-битные указатели.** Пока нативный код живёт рядом с guest-памятью, он
  работает с big endian полями и 32-битными guest-указателями. Это дисциплина `be<T>` и
  трансляции адресов, а не нативные C++-объекты. Полностью нативные объекты возможны только
  после переноса целой подсистемы.
- **Лицензии.** GPL-3.0 (PvZ TV Touch) несовместим с закрытым кодом; LGPL-3.0 (PvZ-Portable)
  накладывает условия на линковку; CC0 (Patoke) свободен. Все декомпиляции производны от
  кода PopCap/EA: юридический статус у них тот же, что у рекомпиляции. Ассеты, как и сейчас,
  только из копии пользователя.

## Рекомендуемый первый шаг

План работ с карточками задач для агентов и порядком приёмки — [native-port/README.md](native-port/README.md).

Построить карту имён Xbox ↔ Android по vtable (B.1). Скрипт-анализатор в `scripts/`
по образцу `inspect_cross_platform_code.py`, результат — JSON/TOML имён с уровнем
уверенности для каждого совпадения. Это не меняет поведение порта. Это сразу показывает
реальное покрытие и даёт основу для любого из вариантов A–C.
