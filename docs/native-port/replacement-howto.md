# Шаблон одной нативной замены

Пилот: `src/native/pixel_to_grid_x.cpp`, Xbox `82149538`.
Обычный запуск сохраняет оригинал. Замена включается явно:
`--pvz_native_pixel_to_grid_x=true`; независимый флаг
`--pvz_native_pixel_to_grid_x_compare=true` выполняет обе версии и возвращает
результат выбранной. В журнале есть аргументы, номер сравнения и число ошибок.

## Выбор и подтверждение

1. Начать с принятого `src/xbox_names.h`. Уверенность medium не становится high
   из-за самого факта экспорта. Если подходящего чистого метода в карте нет,
   согласовать исключение до замены; доказательство имени добавить в отчёт.
2. Прочитать целое тело Xbox и все ветви. Отсутствие прямого store не доказывает
   чистоту: вызываемый метод может менять RNG, звук, объекты или время.
3. Зафиксировать SHA-256 образа, generated-представления, раскладок и новой
   реализации в своей рабочей копии. Отличие CRLF от LF не исправлять под старый
   SHA: сравнивать смысл отдельно, записать фактические хеши.
4. Выписать ABI: входные GPR/FPR, signedness и ширина возвращаемого результата,
   входные/выходные области памяти, допустимые диапазоны и дочерние вызовы.

## Код и переключение

В отдельном `src/native/<name>.cpp` зарегистрировать bool cvar с default=false и
`REX_HOOK_RAW(sub_XXXXXXXX)`. Добавить только этот файл в `PVZ_SOURCES`.
Первый путь хука без активных флагов сразу вызывает
`__imp__sub_XXXXXXXX(ctx, base)` и возвращается; не читать в нём игровые поля.

Поля читать через принятые `src/xbox/*.h`: `rex::be<T>` преобразует endian,
`GuestPtr` остаётся 32-битным адресом и разрешается относительно `base`.
Guest-структуры не имеют host vptr, владельцев памяти и обычных C++ указателей.
Не прятать новые смещения в pad или `reinterpret_cast` к выдуманному классу.
Новый неизвестный field требует отдельного доказательства/раскладки.

Копировать `PPCContext` для shadow-вычисления можно только при отсутствии
побочных эффектов: копия контекста **не копирует guest-память**. Побочные эффекты
нельзя безопасно выполнить дважды. Чистому дочернему вызову передать те же
аргументы; это не означает, что он тоже заменён нативным кодом.

Если хук содержит правленую копию тела из `generated/` (как `src/gamepad_repeat.cpp`),
добавить для неё CTest по образцу `scripts/check_gamepad_repeat_body.py`: перечислить
вставки с соседними строками, остальное сравнивать построчно с текущим `generated`.

Сравнивать ABI-результат и доказанные выходные байты, а не все volatile-регистры
и scratch stack. Не использовать epsilon, если исходный контракт — точные
целочисленные значения или биты float. Контекст реального оригинала сохраняет
свои side effects; при выборе native переопределять только доказанные выходы.

## Проверка

Сначала собрать worktree и выполнить `.\build.bat test`. Затем сравнить функции
на границах области аргументов и в живой игре, записав отдельно синтетические
и реальные вызовы. Меньше 10 000 реальных сравнений нельзя выдавать за выполненный
порог 10 000; нулевой охват конкретного replay также указывать явно.

Выполнить отрицательный контроль: намеренная ошибка native должна дать mismatch
с аргументами. В пилоте это отдельный диагностический
`--pvz_native_pixel_to_grid_x_inject_error=true`, действующий только при compare.
При выключенной замене реальная игра всё равно получает результат оригинала;
при включённой замене ошибочный native-результат действительно будет выбран.
Не включать этот флаг в положительные сравнения.

Для снимков нужны **все пять** сценариев T05b/T05c и три параметра:

```text
--pvz_deterministic_seed=42
--pvz_replay_frame_locked=true
--pvz_deterministic_clock=1792195200
```

Вначале записать исходный секундный replay с
`--pvz_replay_record_steps=true` и теми же seed/часами/профилем; преобразовать его
`scripts/replay_seconds_to_steps.py` по фактическому журналу. Не умножать секунды
на предполагаемый FPS. Пошаговый CSV неизменен между original/native.
Подробности — `state-dumps.md`.

Для двух процессов брать отдельные копии одного полного начального профиля,
тот же EXE, replay и параметры (различается только флаг выбора). Сохранять SHA
входов и точные команды отдельно для каждого запуска. После запуска требовать
GPU-ready, отсутствие fatal и ошибок replay, завершение replay, полное окно
state frames и нужный mode/scene. Выход smoke survived не доказывает охват игры.

```powershell
python -I scripts/compare_state_dumps.py ORIGINAL.jsonl NATIVE.jsonl --output comparison.json
```

Сравнение строгое: никакого удаления полей, выравнивания кадров или изменения
ожиданий в checkers. Проверить выбранные Edge-Tests с реальными вызовами и
штатные регрессии. Известный дефект baseline отделить от новой ошибки по
контрольному прогону, не ослаблять проверку.
