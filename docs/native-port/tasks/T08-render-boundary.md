# T08. Граница рендера Sexy::Graphics на Xbox: исследование

**Этап:** исследование границ · **Зависит от:** T01 (принятая) · **Объём:** средний · **Меняет поведение игры:** нет

## Цель

Выяснить, можно ли рисовать игру нативно, перехватив API `Sexy::Graphics`, а не
эмулируя Xenos GPU. Это путь к высокому разрешению, широкому экрану и исправлению
артефакта Zombiquarium. Результат — проектный документ, не код.

## Вопросы

1. Какие функции `Sexy::Graphics`, `Sexy::Image`/`MemoryImage`, `ImageFont` и Xbox-бэкенда
   (`NativeDisplay`, `Sexy::D3DInterface` в RTTI) вызываются игрой? Адреса, имена, сигнатуры.
2. Сколько их вызывается за кадр в типичных сценах (меню, Adventure, Zombiquarium, Versus)?
   Измерить счётчиками под диагностическим флагом.
3. Какое состояние несёт `Graphics`: трансформация, клип, цвет, режим смешивания, аддитивный
   режим. Где игра обходит `Graphics` и обращается к D3D напрямую (частицы, `PoolEffect`, Reanim)?
4. Как текстуры загружаются из PTX и связываются с `Image`. Можно ли получить исходные пиксели
   до загрузки в GPU?
5. Что из этого перехвачено портом уже сейчас (T03).
6. Сравнить с бэкендом PvZ-Portable (SDL + OpenGL ES 2) по списку операций, **без копирования кода**.

## Результат

`docs/native-port/render-boundary.md`: таблица функций границы, частоты вызовов, обходы,

счётчики — только если нужны, в одном новом файле `src/render_probe.cpp` под флагом.

## Критерии приёмки

- [ ] Каждая функция границы имеет адрес и имя high или доказательство из Xbox-кода.
- [ ] Частоты вызовов измерены на запуске, а не оценены; указаны сцены и число кадров.
- [ ] Все найденные прямые обращения к D3D мимо `Graphics` перечислены с вызывающими функциями.
- [ ] Вывод «можно / нельзя / можно с условиями» обоснован данными таблицы.
