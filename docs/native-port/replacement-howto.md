# Нативная замена и воспроизводимое доказательство

Одна замена — один translation unit в src/native/, контракт выходов и
PVZ_NATIVE_REPLACEMENT. По умолчанию вызывается __imp__ после проверки
одного статического bool; guest-память и механизм сравнения не затрагиваются.
Пилоты: pixel_to_grid_x.cpp и tool_rect.cpp; доказательства — T06/T10.

ReplayCompleted вызывается после обоих сообщений о завершении реплея в
src/input_replay.cpp. Отсутствие точной replay_end-сводки runner считает ошибкой.
Под frame-locked replay host-меню открывается синхронно на UI-потоке: публикация
open/отмены указателя завершается до продолжения текущего логического шага.
Обычный Deferred-путь сохранён; причина и отдельное согласование — в T10.

## До реализации

До чтения первого тела запустить таймер. Вести отдельно заглушки (`blr`,
константный возврат) и остальные функции: время разбора и реализации, затем
время сборки и доказательства. Записывать начало/конец и перерывы; timestamps
готового файла не заменяют это измерение.

1. Выбрать имя из src/xbox_names.h либо доказать его по полному Xbox-телу
   в отчёте. Имена и алгоритмы Android/PC — ориентиры; адреса, ABI, константы
   и записи в память подтверждать в .cache/pvz-image.bin и generated/.
2. Выписать входные регистры, ширину и signedness выходов, все stores и дочерние
   вызовы. Проверить RNG, время, IO, аллокации и события у каждого ребёнка.
   Временный PPC-стек также является памятью: Zen-helper PixelToGridX пишет
   четыре 8-байтовых слота entry.r1-32 .. entry.r1-1.
3. Для compare разрешены только функции с эффектами в объявленных выходах.
   Диапазоны должны быть доступны для записи, не пересекаться, не наблюдаться
   асинхронно и вычисляться из входных аргументов до вызова. Вход/выход может
   совпадать; механизм сохраняет исходные байты до исполнения native.
4. Если перечислить эффекты нельзя, указать Safety::SnapshotsOnly.
   В пакете compare только наблюдает оригинал один раз; standalone compare
   отвергается. Для рисования добавить original/native трассу Graphics;
   снимки состояния сами по себе отрисовку не проверяют.
   Признак — декларация проверенного контракта, а не автоматический анализ stores.

## Объявление

Пример для знакового 64-битного результата в r3 и 16 байт по входному r4:

~~~cpp
#include "native/replacement.h"
#include <array>
namespace {
void Native(PPCContext& ctx, uint8_t* base) { /* по проверенному Xbox-телу */ }
const std::array outputs{pvz::native::RegisterOutput{
    "r3", &PPCContext::r3, 64, pvz::native::Kind::Signed}};
auto Ranges(const PPCContext& input) {
  return std::array{pvz::native::Range{input.r4.u32, 16}};
}
}
PVZ_NATIVE_REPLACEMENT(example, sub_XXXXXXXX, Native,
    pvz::native::Safety::DeclaredOutputsOnly, outputs, Ranges)
~~~

Добавить cpp в PVZ_SOURCES. Для отсутствующих регистров/памяти использовать
std::array<RegisterOutput, 0> / std::array<Range, 0>. У compare должен быть
хотя бы один выход. GPR поддерживают 8/16/32/64 бита и Signed/Unsigned;
выбранный узкий результат соответственно sign/zero extended. FPR объявляются
через &PPCContext::fN, Kind::FloatBits, 32 или 64 бита. FPR32 сравнивает биты
float(fN.f64), FPR64 — все биты регистра; epsilon не применяется.

Макрос создаёт три выключенных флага, читаемых при старте:

| Флаг | Действие |
|---|---|
| --pvz_native_example=true | выбрать native |
| --pvz_native_example_compare=true | исполнить обе версии и сравнить выходы |
| --pvz_native_example_inject_error=true | изменить младший бит первого выхода только в compare |
| --pvz_native_compare_all=true | compare всех зарегистрированных замен |

Инъекция меняет первый регистр, а при его отсутствии — первый выходной байт.
При compare с выключенным выбором native в игре остаётся original. Последовательность:
копия входного контекста и байтов → native → сохранение native-байтов → восстановление
входных байтов → original → сравнение → при выборе native перенос только объявленных
регистров/байтов. Scratch-регистры сохраняются от original. Без compare вызывается
только выбранная реализация; inject в таком режиме не действует.

Игровые поля читать через принятые src/xbox/*.h / guest_memory.h.
Нельзя переносить Android-смещения, копировать GPL/LGPL-код либо скрывать
непроверенное поле в padding. Для новых раскладок требуется отдельное согласование.

## Журнал и принудительное завершение

Каждый mismatch содержит номер вызова, входные GPR/FPR и отличающиеся регистры/
байты. Сводка «PvZ native <name> summary reason periodic comparisons N errors E»
пишется каждые 1000 сравнений. Сводка replay_end фиксирует границу реплея,
включая нулевой охват. В той же строке записаны первые 16 различных входных
ctx.lr с числом сравнений/ошибок, остальные — в other; сумма обязана совпадать
с общими счётчиками. Счётчики после этой границы могут продолжать расти.

При заданном штатном log_file рядом создаётся
<log_file>.<name>.native-counts.bin. Это отображённый в память файл с точными
счётчиками завершённых сравнений после остановки процесса. Формат: ASCII
PVZNR001, затем два слота из трёх little-endian u64: generation, comparisons,
errors (всего 56 байт). Новая запись инвалидирует один слот, записывает payload
и атомарно публикует generation=comparisons. Читать старший валидный слот;
незавершённая запись не уничтожает предыдущую. Подробные расхождения остаются
в журнале, а на каждом вызове нет отдельной записи журнала или системного вызова.
Это защита от остановки процесса, не от потери питания/диска.

Подробная строка записывается только для первых **20 расхождений на замену
за процесс**. Все остальные ошибки по-прежнему входят в `errors`, LR-разбивку,
периодические сводки и mapped checkpoint. Число подробных строк больше не
равно числу ошибок; для отрицательного контроля использовать точную сводку.

## Выбор доказательства и пакет

| Контракт | Проверка | Ограничение |
|---|---|---|
| Все эффекты перечислены в выходах, есть игровой охват | `DeclaredOutputsOnly`, compare в игре + отрицательная инъекция | Нулевой охват не является доказательством |
| Все эффекты перечислены, сценарии функцию не вызывают | `SyntheticInputs` + `VerifySynthetic` против исходной generated-функции | Изолированные буферы; границы обязательны, случайная часть с фиксированным seed |
| Рисование и дочерние эффекты | `SnapshotsOnly`, трасса Graphics original/repeat/native | Трасса вызовов дополняет снимки, не доказывает равенство GPU-пикселей |
| Аллокации, callbacks, события, RNG/IO | `SnapshotsOnly`, одинаковые снимки и целевой сценарий | Перечислить непроверенные ветви; не исполнять дважды в одной guest-памяти |

Новый пакет объявляется в **своём** cpp, до регистраций:

~~~cpp
PVZ_NATIVE_BATCH(b002)
PVZ_NATIVE_BATCH_REPLACEMENT(b002, false, example, sub_XXXXXXXX, Native,
    pvz::native::Safety::DeclaredOutputsOnly, outputs, Ranges)
~~~

Это создаёт `--pvz_native_b002` и `--pvz_native_b002_compare`, init-only и
выключенные по умолчанию. В `replacement.h/.cpp` имён пакетов не добавлять.
`PROVEN=false` сохраняется до доказательства; индивидуальные флаги доступны
для исследования. В CSV хранить вид доказательства отдельно от игрового охвата:
`synthetic` не означает реальные вызовы в реплее. Сам runner пока знает набор
сценариев B001; добавление нового пакета требует собственного состава и контрактов.

Образец входных доменов — `src/native/b001_widget.cpp`, выбор домена рядом с
каждым `LEAF`. Он задаёт регистры, поля Xbox Widget, границы, seed и алиасы.
`tests/b001_synthetic_sources.py` извлекает **дословные** generated-тела в build,
фиксирует SHA-256 входов и не переписывает эталон. Тест сравнивает объявленные
регистры побитно и байты диапазонов на независимых буферах с выравниванием 32.
Инъекция младшего бита проверяется на каждом входе. Невалидные указатели,
trap-контракты и незавершающиеся входы нельзя молча исключать: границы домена
и причина неполного доказательства должны быть в таблице и отчёте.

~~~powershell
.\build\b001_synthetic_test.exe runtime-data/b001-synthetic.json
pwsh -NoProfile -File scripts/run_native_proof.ps1 -Batch b001 -RenderOnly
~~~

Полный `-Batch b001` включает синтетику и фазу трассы для `SnapshotsOnly`.
Трассу включает `--pvz_native_render_trace=<jsonl>`; нужен
`--pvz_replay_frame_locked=true`. `--pvz_native_render_steps=N` задаёт точное
число завершённых кадров. Диагностика разрешает следующий реальный app update
после первого DrawScreen (`824A7190`) предыдущего шага. Повторные draw того же
шага не записываются. Записываются Graphics-вызовы внутри динамического
контекста зарегистрированной замены пакета, с входными аргументами, текстом UTF-16
в hex и актуальным состоянием Graphics (также после inline-записей).
Это ограниченная граница T08: прямые D3D/Tod-вызовы вне Graphics не покрываются.
Font/Image записываются по Xbox-полям имени ресурса и его параметрам, поскольку
адреса аллокатора между процессами меняются. Для неизвестного ресурса сохраняется
адрес; такой объект нельзя молча приравнять по порядку появления или размеру.
Для Versus runner фиксирует `--pvz_controller_glyphs=xbox`. Подсказка второго
игрока всё равно чередует Xbox/PlayStation раз в секунду, пока тип контроллера
неизвестен. В диагностическом режиме оба её host-clock чтения используют
`replay_step / 100` (шаг T12 равен 10 мс), сохраняя само чередование.
`controller_assets.cpp` явно вызывает `RenderClockSeconds()`; без флага трассы
эта функция возвращает прежние `steady_clock` секунды. Существующие Graphics-
хуки явно вызывают `TraceGraphics()` до адаптации аргументов, а хук обновления
в `deterministic_replay.cpp` — `HoldRenderUpdate()`. Объявления находятся в
`src/native/render_trace.h`; CMake собирает исходные файлы без текстовой подмены
и переименования символов. Трассы не нормализуют и не объединяют атласы.
Сравнение требует непрерывных шагов и footer; первая разница содержит шаг,
индекс вызова, scope, операцию и оба набора аргументов. Ошибка `Centered`
под `--pvz_native_widget_82473730_inject_error=true` сдвигает x на один.

`-RenderOnly -ReuseEvidence <старый OutputRoot>` повторно читает только
законченные игровые процессы того же EXE с теми же scalar flags, кадрами,
профилем/реплеями и SHA manifest/log/dump/trace. Изменившийся сценарий запускается
заново. Для сверки новой версии verifier сохраняются `runner-input.ps1` и
хеш исходного summary; изменение игровых исходников/таблицы запрещает reuse.

`smoke.ps1` передаёт проверяющим исходные журналы, включая ротированные.
Производные `.checker.log` больше не нужны: пять проверок завершения принимают
оба маркера `PvZ replay completed` и `PvZ frame replay completed`.

## Проверка одной командой

Сначала собрать EXE и тесты:

~~~powershell
.\build.bat configure
.\build.bat
.\build.bat test
.\scripts\run_native_proof.ps1
~~~

Runner повторно использует run_determinism_check.ps1. По умолчанию берёт пять
принятых шаговых CSV и JSON конвертации из tests/replays/native-proof/.
Каждый процесс использует один неизменный steps CSV на сценарий,
отдельные копии одного профиля, seed=42 и clock=1792195200.
Времена и окна T05 сохранены: Adventure 5000, Versus 6000, Heavy Weapon 3000,
Zen 5000, меню 5000. Нужны baseline runtime-data/zen-shop-probe-user, игровой
образ и собранный build/pvz-console-edition.exe.

Ранее записанные шаги можно передать через -ReplayDirectory <каталог>:
adventure.csv, versus.csv, minigame.csv, zen.csv, menu.csv.
Они получают SHA-256 и не переписываются. Запись пяти seconds CSV и конвертация
реальных шагов доставки через replay_seconds_to_steps.py включаются явно: -Record.
Открытый вопрос нового record/Zen с неполным окном сохранён в T10; принятые
CSV от этого пути не зависят. Повторный запуск использует новый -OutputRoot.
Параметр -Cases предназначен для диагностики; приёмка требует все пять сценариев.
Нужны ≥10 000 реальных сравнений на замену по сумме сценариев отдельно в каждом
повторе. Меню с нулём вызовов записывается явно; меньший охват не принимается.

Проверяются: compare с выбранным original дважды; ошибки и охват каждой замены;
одинаковый успешный итог повторов; снимки off/compare-original; снимки off/native-only
отдельно для каждой замены; inject_error на сценарии с максимальным охватом.
Каждый процесс обязан пройти smoke/GPU/fatal/replay/full-frame/playing-mode проверки.
Сравнение состояния строгое через неизменённый compare_state_dumps.py.

summary.json и summary.md содержат итог каждого критерия, SHA входов, команды,
счётчики на границе replay и точные счётчики остановленного процесса. Ненулевой
код означает провал или неполное доказательство. По решению приёмки T10 счётчики
справочные: render/host-зависимые вызовы не обязаны повторяться численно.
Норма — 0 ошибок, достаточный охват, равные снимки, пойманная отрицательная
инъекция и тот же итог повторного прогона. Разбивка LR не является порогом.

Для проверки чувствительности всего runner можно намеренно включить инъекцию
через -InjectError (для всех выбранных замен) либо
-AdditionalGameArgs '--pvz_native_example_inject_error=true':
положительный compare обязан провалиться. Обычные прогоны этот аргумент не используют.

CTest native_replacement не запускает игру: поддельный PPCContext и буфер
проверяют восстановление, выбранные выходы, aliasing, FPR, inject, no-flags путь
и 1000-вызовную сводку, первые 16 LR и счётчики остальных вызывающих.
native_proof_parser проверяет разбор ротированных журналов и сумму LR,
отсутствующую/испорченную сводку, нулевой охват и незавершённый checkpoint.

## Отчёт и приёмка

Приложить: диапазоны PPC и полный контракт с уровнем достоверности; SHA образа,
generated/раскладок/EXE/native; точную команду; summary и сырые manifests/logs/dumps;
реальные и синтетические счётчики отдельно; нулевой охват сценариев; отрицательный
контроль; повтор на том же EXE; штатные регрессии без флагов. Нестабильные проверки
отделить контрольной сборкой master, сохранив исходные отказы и прежние ожидания.
README, generated и игровые образы не менять; scripts/check_* допускают только
согласованную T14 правку маркера завершения. Не коммитить,
не включать native по умолчанию, не переносить в master без отдельного поручения.
