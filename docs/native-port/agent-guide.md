# Правила для агента-исполнителя

Прочитать целиком до начала работы. Карточка задачи (`tasks/Txx-*.md`) уточняет эти
правила, но не отменяет их. Если карточка с ними расходится, остановиться и спросить.

## 1. Что за проект

Статическая рекомпиляция Xbox 360 Plants vs. Zombies (XBLA, TitleID `584109FF`,
`default.xex` 0.0.1.4) через ReXGlue в x86-64 Windows. PowerPC-код игры переведён в C++ в
`generated/` (20 999 функций `sub_XXXXXXXX`). Порт меняет поведение хуками
`REX_HOOK_RAW(sub_X)` в `src/`; оригинал вызывается как `__imp__sub_X(ctx, base)`.
Данные игры лежат в guest-памяти: big endian, 32-битные указатели. Доступ — через
`src/guest_memory.h`, известные адреса — `src/guest_layout.h`.

Начать с [technical-notes.md](../technical-notes.md),
[native-port-feasibility.md](../native-port-feasibility.md) и
[cross-platform-research.md](../cross-platform-research.md).

## 2. Источники и их вес

| Источник | Где | Чему верить |
|---|---|---|
| **Xbox** — образ памяти и сгенерированный код | `.cache/pvz-image.bin` (база `0x82000000`), `generated/default/*.cpp` | **Единственный источник истины** для поведения, адресов и смещений |
| Android TV 1.1.5, оригинальный APK | `Chinese Android TV Image/`, символы — `research/cross-platform/android-symbols.json` | Имена функций и классов, порядок vtable, форма алгоритма. Смещения полей **другие** |
| Мод PvZ TV Touch (GPL-3.0) | [ZombieYetis/PlantsVsZombies-AndroidTV](https://github.com/ZombieYetis/PlantsVsZombies-AndroidTV) | Раскладки классов и разобранные функции **именно нашей** сборки Android 1.1.5 (константы `PVZ_VERSION == 115`). Только как справочник |
| PC-декомпиляция 1.0.0.1051 (MIT) | `research/pvz-pc/` | Читаемый исходник общих классов. Другая ветка: консольных классов и второго игрока нет |
| PS3 / Vita | `research/cross-platform/` | Исходники анимаций (PS3), сенсорная ветка (Vita) |

Любой факт об Xbox, взятый из Android, PC или мода, — **гипотеза, пока он не подтверждён
по Xbox-коду**. Пример расхождения: SeedBank в Board лежит на Android по `+20C`, на Xbox — по `+1A4`.

## 3. Жёсткие ограничения

- **Не менять** `generated/`, `assets/`, образы игр (`Chinese Android TV Image/`,
  `PS3 Image/`, `*.iso`, `Plants vs. Zombies*/`), `.cache/`, `research/pvz-pc/`,
  `research/rexglue-source/`. Это входные данные.
- **Не коммитить, не переключать ветки, не делать push**, если карточка не требует иного.
  Изменения остаются в рабочем дереве; принимает их проверяющий.
- **Не удалять рабочие деревья и папки рекурсивно.** Worktree этого репозитория содержат
  junction-ссылки на основную папку (`assets`, `generated`, `.cache`, `tools`, `research`,
  образы игр). Рекурсивное удаление и `git worktree remove` проходят по ссылке и стирают
  данные основной папки. Убирать worktree — только после снятия каждой ссылки
  (`cmd /c rmdir <ссылка>`) и с согласия владельца.
- **Трогать только файлы из раздела «Результат» карточки.** Нужен другой файл — объяснить
  в отчёте, зачем, и не править его без согласования. Параллельно работают другие агенты.
- **Не копировать код** из мода PvZ TV Touch (GPL-3.0) и PvZ-Portable (LGPL-3.0): лицензия
  порта не выбрана. Разрешено брать факты (имена, смещения, порядок полей, значения
  констант) со ссылкой на файл и строку источника. Код PC-декомпиляции (MIT) можно
  использовать как основу с пометкой происхождения.
- **Не менять поведение игры** в задачах этапа «Знание» (T01–T04, T08, T09).
- **Не подгонять пороги и тесты под желаемый результат.** Если метрика не сходится,
  сообщить об этом в отчёте, а не ослаблять проверку.
- Не скачивать сторонние бинарники и не запускать их. Чтение GitHub через `gh api` или
  веб-страниц — можно, если карточка этого требует.

## 4. Инструменты и окружение

- Windows, PowerShell по умолчанию; Git Bash тоже доступен.
- Python 3.10+. Сторонние пакеты (Capstone, Pillow) лежат в `tools/python`; скрипты
  добавляют эту папку в `sys.path` (образец — `scripts/inspect_cross_platform_code.py`).
  Запускать с `-I`, когда скрипт читает данные игр.
- Bash heredoc портит `\n`/`\0` в коде; Python-скрипты писать файлами, а не heredoc.
- Сборка и модульные тесты: `.\build.bat test`. Запуск игры для проверки: `.\smoke.ps1`
  с аргументами `--pvz_input_replay=<csv>`, `--pvz_capture_frame`, `--pvz_test_unlock=true`
  (примеры — `technical-notes.md`, `scripts/run_*_regression.ps1`). Реплеи — `tests/replays/`.
- Ghidra MCP может быть подключён к сессии; без него — Capstone по `.cache/pvz-image.bin`.
- Существующие анализаторы для переиспользования: `scripts/analyze_cross_platform.py`
  (ELF, PAK, `save_json`), `scripts/inspect_cross_platform_code.py`,
  `scripts/name_xbox_from_android.py` (черновик T01).

## 5. Где хранить результат

| Что | Куда |
|---|---|
| Воспроизводимые анализаторы | `scripts/<имя>.py`, с docstring: входы, выход, метод |
| Крупные выводы анализаторов | `research/cross-platform/…` (в `.gitignore`; должны пересоздаваться скриптом) |
| Небольшие проверенные таблицы для git | `docs/native-port/data/` |
| Код порта | `src/`, только если карточка это разрешает |
| Отчёт | `docs/native-port/reports/Txx.md` |

Каждый вывод скрипта содержит SHA-256 входов, чтобы проверяющий понял, на чём он получен.

## 6. Достоверность

- У каждого утверждения есть способ проверки: команда, адрес, вывод, строка источника.
- Уровни: **проверено** (на Xbox-коде или запуском), **подтверждено косвенно**
  (несколько независимых признаков), **гипотеза**. Писать уровень явно.
- Числа в отчёте пересчитываются командой из отчёта. Никаких оценок «примерно» без пометки.
- То, что не удалось проверить, перечислить отдельно. Это не провал, а нормальная часть отчёта.

## 7. Отчёт

Файл `docs/native-port/reports/Txx.md`, по-русски, в стиле остальных `docs/`:

1. **Итог** — 2–4 предложения: что сделано и в каком состоянии.
2. **Изменённые файлы** — список с назначением каждого.
3. **Как воспроизвести** — точные команды из корня проекта.
4. **Результаты** — числа и таблицы, каждое с уровнем достоверности.
5. **Критерии приёмки** — каждый пункт карточки: выполнен / не выполнен / частично, с доказательством.
6. **Не проверено и риски.**
7. **Вопросы к владельцу** — решения, которые агент не вправе принять сам.

Статус в таблице `README.md` агент не меняет.
