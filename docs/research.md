# PvZ XBLA: проверенные точки интеграции

Исследование выполняется по локальному XEX, версия 0.0.1.4. Образ загружается SDK и при необходимости сохраняется `pvz_inspect`, затем анализируется PowerPC big endian. В таблицах RTTI найдены имена классов и их vtable; интерфейсы сравниваются с PC SexyApp. Поля PC-версии напрямую в Xbox-память не переносятся.

## Образ

- TitleID: `584109FF`, MediaID: `528550BC`.
- Image base: `82000000`, размер `00DC0000`.
- Код: `82120000 .. 827B8A18`, entrypoint `822CB9D0`.
- XEX SHA256: `46aa9531a4091be2fdeb532a14a0f31c5547d248a6868d9f7d65b119b2005d21`.
- Извлечены 24 файла STFS; SHA1 проверяется у каждого блока данных, SHA256 сохраняется в локальный отчёт.

Мышь публикует снимок позиции и очередь переходов down/up. Guest memory меняется только при обработке на игровом потоке. Вызовы обработчиков выполняются с копией PPCContext и отдельным местом под caller frame; регистры вызывающей функции сохраняются. Прямоугольник презентации учитывает `present_letterbox`; координаты событий SDK — физические пиксели. В рантайме подтверждён WidgetManager 800×600 при framebuffer 1280×720.

В console Board почти все mouse-методы базовые; специфические callbacks служат главным образом Zen Garden. В одиночном Adventure выбор карточки хранится на стороне мостика, её индекс записывается в Controls+BC только после CanPickUp. Нажатие по клетке вызывает исходный Board::GamepadButtonDown(A): расходы солнца, ограничения посадки, обучение и перезарядка остаются в игре. Изменение SeedPacket+68 подтверждает посадку. Пока карточка не выбрана, автоматический геймпадный preview убирается после Update; ПКМ отменяет выбор. Для остальных режимов остаётся прежняя маршрутизация gamepad actions; Zen Garden получает собственные mouse callbacks.

`pvz_cursor_mode` — строковый cvar с allowed values pc/console и сменой во время работы. Описанная выше ручная карточка и скрытие preview относятся к pc. В console координаты 74/78 обновляются только при новом положении мыши; результат native Update не перезаписывается. В одиночном Adventure, вне SeedBank и после вступления, SetState(4) включает штатное притягивание после отпускания стика: StateEnter 82190048 вычисляет цель 58/5C через виртуальный метод +24 (82190ED8), StateUpdate 821905F8 двигает курсор к ней. Состояния специальных инструментов 5/6 не заменяются. При возврате в pc SetState(1) прекращает прежнее притягивание. Клик по карточке в console записывает BC без посадки; другие клики передают исходные A/B down/up. Первичный контроль и Adventure проверяются перед доступом к SeedBank.

Автоматический сбор coins из Controls::Update определяется по адресу возврата 8218C1C4. Для мыши первого игрока в Adventure с логикой pc этот вызов пропускается у типов 1–7; ЛКМ собирает солнце, обычные монеты и наградную карточку нового растения через Board::MouseHitTest и Coin::Collect. В console этот вызов сохраняется. Другие типы, игроки, игровые режимы и scripted calls сохраняют исходное поведение. Успешный сбор подтверждается переходом Coin+84 в 7, а не фактом вызова функции: она может отклонить ещё появляющееся солнце или уже собираемый объект.

Физические события сначала нормализуются относительно презентации кадра. Затем координаты переводятся из нормализованного экрана 800×600 в центрированную плоскость UI/Board: x=1.6*x−240, y=1.2*y−60. Это относится к закреплённой версии с гостевым framebuffer 1280×720. Во время вступительной панорамы Board дополнительно сдвигается; посадка доступна после её завершения. Тесты отдельно проверяют границы этой плоскости.

Все `GameButton` главного меню имеют стандартные mX/mY=0, хотя картинки размещены по панорамному экрану. `MainMenu` использует анимации/трансформации; обычный `WidgetManager::GetWidgetAt` возвращает фон или кнопку с неверным Widget rect. На стабильной центральной панели используется измеренная карта кнопок и четыре круглых области подсолнухов (ID 4–7). Hover задаётся SetGamepadFocus, активация — исходным ButtonDepress; down/up должны попасть в одну кнопку. Поля 118/11C — текущая/целевая панель (0 More Ways, 1 центральная, 2 Extras). Для панелей 0/2 используется фактическая позиция GameButton 19C/1A0 либо 190/194 и размеры 1A4/1A8 с базовым масштабом. Эти позиции уже включают прокрутку и находятся в пикселях полного framebuffer 1280×720: экранный point умножается на 1.6/1.2 без смещения Board. ID 9 Back, 10 VS, 11 Co-op, 12 Mini Games, 13 Survival, 14 Puzzle; ID 15 Back в Extras и 19 Mail. Для стабильной панели допускаются только её ID, а скрытые кнопки (149, ранний выход из Draw) исключены. Во время прокрутки клики поглощаются без native MouseDown, чтобы не захватывать кнопки с ложным rect 0,0. Native MousePosition получает нормализованную позицию по всему окну, когда верхний root — MainMenu; координаты Board/диалогов по-прежнему пересчитываются отдельно.

Adventure имеет два native widgets: ID 0 Start Adventure и ID 1 Adventure с прогрессом. На копии профиля уровня 1-3 трасса подтверждает visible+70=0 у ID 0 и =1 у ID 1. Таблица ButtonDepress 821C0B68 направляет оба ID в 821C0BB8. Геометрическая карта возвращает область 0, но мостик разрешает её в видимый/доступный widget через FindMenuButton (70/72/149), без чтения или изменения сохранения. Этот же выбор используется для восстановления фокуса контроллера на центральной панели.

Звук hover: исходный ButtonWidget::MouseEnter (824AE518) вызывает ButtonListener+10, но MainMenu listener (820C28FC) использует пустой 821770E8. Мостик отслеживает реальный переход на новую кнопку в обоих режимах, вызывает исходные MouseEnter/MouseLeave (824AE610) и для пустых listeners воспроизводит загруженный SOUND_BLEEP. Global 82D0A4F8 подтверждён загрузчиком ресурса SOUND_BLEEP (имя 820C99D4, запись 821FDB8C). Используется LawnApp virtual PlaySample +E0 (821ABDE8 → 82477418); громкость/отключение звука и создание sound instance остаются в исходной игре. Трасса сохраняет возвращённый instance; ненулевые instances подтверждены в реплее. Native MouseEnter для GameButton подавлен только при включённом мостике, чтобы неверные Widget rect не создавали лишние sounds; синтетический переход вызывает original entry. Старый указатель hover не разыменовывается после закрытия UI: сначала проверяется его наличие в текущем дереве widgets.

В диалогах применяется другая геометрия: у GameButton/его диалогового подкласса положение отрисовки находится в 190/194 либо 19C/1A0 при флаге 198, размер — в 1A4/1A8. К нему прибавляются смещения Widget parents. Draw масштабирует картинку вокруг центра (Graphics::SetScale 8249B508); области попадания учитывают базовые масштабы 1C4/1C8, без пульса наведения 1CC/1D0. Найденная кнопка получает SetGamepadFocus и исходную пару GamepadButtonDown/Up(A). Клик отпускается над той же кнопкой; отмена сбрасывает pressed flag. Обычный drag диалога остаётся на native mouse callbacks вне кнопок. MainMenu исключён из этого пути, поскольку использует отдельную панорамную трансформацию.

На TitleScreen ЛКМ вызывает исходный GamepadButtonDown(A), который проверяет завершение загрузки перед переходом. Реплей умеет wait_title/wait_menu/wait_board; ожидание TitleScreen само не активирует экран. Готовность публикуется атомарно игровым потоком; worker реплея не читает guest memory. Ожидание приостанавливает часы сценария и прекращается по stop token или через 90 секунд. Это устраняет зависимость от длительности загрузки и вступительной панорамы.

## Исправления рекомпиляции

Внутриигровые настройки: `game_settings.cpp` добавляет native DialogButton ID 1002 в HelpOptionsDialog (vtable 820BAA54). AddedToManager 82198850 создаёт кнопку через MakeDialogButton 82188F80 и добавляет её в WidgetContainer (82493E10). Resize 82198938 размещает её в свободной строке y=306 между Credits (254) и Back (371); ширина/позиция x берутся у Back. В игровом Options предыдущий пункт — Settings, поскольку Credits отсутствует. Навигация up/down использует native pointers +B0/+B4. Listener ButtonDepress 82198B30 (this=dialog+D4) обрабатывает только ID 1002, меняет `pvz_cursor_mode` и сохраняет только этот корневой TOML-ключ через временный файл и rename. Остальные настройки сохраняются, временные replay/capture/paths из CLI не записываются. Остальные ID передаются исходному коду. Label обновляется при внешнем изменении настройки. RemovedFromManager 821988D0 удаляет кнопку из дерева, деструктор 82198720 освобождает native button; повторное открытие не оставляет старый widget. Строки создаются/удаляются native UTF-16 string routines, PPCContext передаётся явно по регистрам: r3 не соседствует с r4 в host layout.

Полная версия: native LawnApp license check 821AFCA0 вызывает XamContentGetLicenseMask через 822CAA60 → 82759C8C, проверяет бит 0 и кэширует успех в App+A59. В SDK `license_mask` по умолчанию 0. `pvz_full_version=true` перед guest launch выставляет бит 0, false снимает его, другие биты сохраняются. Native проверка остаётся исходной; диагностический хук только логирует её результат. Исходные XEX и STFS не изменяются. Progress locks не обходятся: Puzzle на свежем профиле полной версии показывает Play more Adventure to unlock Puzzle Mode / OK вместо trial upsell.

Автопереключение ввода: `input_backend.cpp` оборачивает выбранный физический SDL/XInput driver **до** объединения с MnK. Назначение устройств остаётся SlotAssignment; отслеживается физический ordinal 0, без второго игрока и синтетических клавиш/мыши. Новые нажатия, движение стика за deadzone 7849 с изменением минимум 1200 и триггера за 30 с изменением минимум 5 публикуют активность. Удержание и отпускание сами не забирают управление. UI и input driver меняют только атомарное владение/очередь; память игры меняется в guest thread. При контроллере ApplyPointer, ПК-фильтр фокуса и подавление автосбора прекращаются. При возврате мыши сбрасываются захваты и выбор карточки, сохраняется предпочтение pc/console. `pvz_input_auto_switch=false` отключает передачу управления контроллеру.

Консольные полосы подсказок рисует общий `sub_82196600`; при активной мыши подавляется только отрисовка. `MessageWidget::Draw` (`821C6468`) отдельно показывает A/B внутри строк. Его UTF-16 label — 128 символов по +20, reanimation type +32C. Для обычного текста (type -1) перед Draw временно заменяются `Press <A>/<B>` и markup `<A>/<B>/<S>` на Left-click/Right-click, LMB/RMB/Enter. Затем весь исходный буфер восстанавливается; таймеры, обучение и возвращение к контроллеру сохраняются. Animated wave messages с отдельными анимациями букв не изменяются. Другие виды встроенных glyphs и экраны вне общего renderer требуют отдельной проверки.

Мигающее приглашение второго игрока с Start рисует `Board::DrawOverlay` (`82146678`). Его исходный ключ `[P2_JOIN]` хранится в UTF-16 string по Board+5864. Только для этого ключа при мыши blink flag +585C временно обнуляется на время Draw, затем восстанавливается. Таймер мигания продолжает Update; контроллер возвращает подсказку. Уведомление `[P2_JOINED]` не скрывается. Отдельный реплей `tutorial_input.csv` проверяет смену ввода во время первого обучения.

Анимация SeedPacket: +70 — float времени выбора, +74 — время пульса, +78 — вычисляемый масштаб. Выбор мышью сбрасывает +70, как native NextSeed/PrevSeed (`821911E0`/`821913A8`). Native Update увеличивает таймер, Draw плавно увеличивает scale до 1.2. Для PC без карточки `SeedBank::Draw` (`82210768`) временно получает Controls+BC=-1; renderer сравнивает индекс и не индексирует через него. После Draw BC восстанавливается: gameplay Update требует действительный индекс. На снятии выбора таймер старой карточки тоже сбрасывается, чтобы исходная анимация уменьшения сохранилась. Контроллер и mouse Console используют обычное постоянное выделение. Выбор растений перед началом уровня (SeedChooser) этой проверкой не покрыт.

ПК-подсветка UI: SetGamepadFocus (824A5F48) вызывал LostGamepadFocus (+AC, 82472C88) и GotGamepadFocus (+A8, 82472C58). GameButton::Draw (82188310) рисует наведение по двум независимым флагам: 75 (mIsOver) и A2 (gamepad focus). Поэтому одного MouseLeave недостаточно. В pc мостик после UpdateFrame (824A6140/824A6198) синхронизирует оба флага с измеренной областью кнопки и сбрасывает gamepad focus на фоне/вне canvas. Хук SetGamepadFocus фильтрует автоматический выбор кнопки исходной игрой. В console этот фильтр и синхронизация отключены. Неверные Widget rect 0,0 больше не создают отдельную подсветку в pc; кнопки диалогов проверяются по их draw rect с учётом положения родителя. DrawStoneButton (82187970) округляет число средних тайлов до ближайшего целого: ширина layout 328 в Help/Options фактически рисуется как 300. Hit area повторяет это округление, читая размеры исходных normal left/middle/right image через globals 82D09F40/82D0A738/82D09EEC; простой прямоугольник шириной 328 подсвечивал кнопку в пустой полосе справа.

`config/analysis.toml` содержит только проверенные подсказки:

1. `8261A850`: thunk `addi r3,r3,8; b 82619230`, размер 8.
2. `82625538`: tail thunk `b 82624A10`, размер 4.
3. `82671E78`: расширен до `826723F0`, чтобы общая ветвь cleanup не стала недопустимым C++ goto в другую функцию.
4. `826230D8` и `8261DFC0`: косвенно достигнуты при загрузке; включены в анализ после ранних fatal.

`camera_compat.cpp` закрывает отсутствующие в пакетном SDK XUsbcam exports. Создание/состояние возвращают отсутствие подключённого устройства, команды камеры — `ERROR_DEVICE_NOT_CONNECTED`, 1167. Поддержка камеры не реализована.

скрывается на время удержания предмета. Общие Graphics DrawImage/DrawVertices
дополнительно исключают родные рамки и тени.

Регрессия Console Mouse: прямой MouseDownWithTool из состояния SHOVEL_PICKUP
(15) удалял все растения, но не запускал переход обучения. Native обработчик
проверяет завершение только в SHOVEL_DIG (16) / KEEP_DIGGING (17). ПКМ теперь
сначала вызывает PickUpTool для состояния 15. После действия проверка
CountPlantByType(0) через 82134748 позволяет восстановить уже зависший экран
без растений через native SetTutorialState(18), 8213D0F0. Пустая клетка при
оставшихся растениях обучение не завершает. Пауза блокирует выкапывание.
После состояния 18 Board продолжает рисоваться вместе с Дэйвом, но mouse
capture и hover могут расходиться: down указывает на Board, up — на пустоту.
ЛКМ в этом состоянии вызывает native CutScene::AdvanceCrazyDaveDialog
(8217D798) через живой Board из корневого дерева, включая disabled widget.
Условия ограничены Intro, активной репликой и отсутствием паузы; обе половины
клика поглощаются. Остальные состояния используют прежний маршрут.

SeedBank 82210768 и PacketDraw 8220E5D0 временно получают Controls+BC=7FFFFFFF
при пустой руке. Значение -1 нельзя использовать: на ленте Packet+48 тоже
бывает -1, что оставляет карточку подсвеченной. Восстановление BC после Draw
сохраняет безопасный индекс для gameplay. PacketUse 82210308 снимает выбор
по указателю использованной карточки, включая сдвигающиеся карточки ленты.
SOUND_SEEDLIFT назначается по 82D0A630 (ID 25), SOUND_BUZZER по 82D0AA24 (ID 5).
CanPickUp 8220F370 решает, какой из двух звуков воспроизвести.

SeedChooser использует Hit 8220AFA8 и родные переходы 8220B1C0/8220B440
для возврата/добавления карточки. EAC применяется только для наведения в Draw;
E7C/E84 хранят tooltip и его seed. Новый native DialogButton ID 100 принимает
LET'S ROCK через исходный listener. Видимый экран ищется в дереве widgets:
последним root часто оказывается прозрачный фон с vtable 820BA804.
Award NEXT LEVEL хранится отдельно от children и использует painted rect
190/194/1A4/1A8, а не пустой Widget rect. Клик вызывает 8212C4D0(A); Draw
8212A658 выставляет 75/A2 только при наведении в PC.

PC Settings расширяет прежнюю кнопку Mouse отдельной страницей с четырьмя
пунктами. Back возвращает исходную страницу; новые widgets удаляются вместе
с родителем. Native Settings 821993F8 скрывает Change Storage по +1D8.
Escape мигрирует только прежнее стандартное назначение Return. Потеря фокуса
в игровом Scene 3 вызывает штатный Start, если Board ещё не на паузе.
VSync меняет runtime vsync и d3d12_allow_variable_refresh_rate_and_tearing;
окно отсоединяет и снова присоединяет Presenter, пересоздавая swap chain.
SDK Present остаётся с SyncInterval=0: запрет tearing использует композицию
Windows, а не жёсткую привязку guest-частоты к частоте монитора.

PS3-пакет использует классический индекс и zlib, а выбранные PTX содержат DDS
DXT5. scripts/extract_ps3_controller_assets.py переводит линейные блоки в
Xbox PTX с 16-битным endian swap, row stride и native footer. Родной loader
82480430 получает файлы через ограниченный whitelist в PakRead 824B2D20.
Буфер обязательно выделяется SystemHeapPhysical с выравниванием 4096:
XGSetTextureAddress интерпретирует адрес как физический, и обычный malloc
приводит к прозрачным текстурам. Буферы сохраняются до завершения runtime,
как исходное отображение packed assets.

Подмена при Draw учитывает и указатель, и исходное имя Image+8: игра создаёт
дополнительные экземпляры ресурсов после начальной загрузки. Атласы native
font glyphs по 828923CC/828923D0 временно прозрачные при мыши; кешированные
команды разрешают актуальный atlas при Draw, поэтому смена ввода обратима.
SDL Sony VID 054C и названия DualShock/DualSense определяют основной геймпад;
XInput-обёртка может скрывать производителя, для неё есть принудительный режим.
Схема DualShock и глифы визуально подтверждены принудительным реплеем,
физическое устройство этим не проверяется.

## Дополнения: текст, курсор и звук (2026-10-06)

`Controls::StateEnter(6)` поднимает лопату и переводит tutorial 15 → 16.
Удержание B читается в `8218B8EC` через `82580A78(button=7)`. Мостик отдаёт
удержание только для основного Controls, пока нажата ПКМ в Console.
Штатный `StateUpdate(6)` ведёт таймер `Controls+70`; `StateExit(6)` (`82190408`)
вызывает ToolMouseDown(6) только при таймере больше 1.0. Выкапывание происходит
при отпускании. При отмене/смене устройства/потере фокуса таймер обнуляется
до выхода из состояния. PC продолжает использовать немедленное действие ЛКМ.

В `Controls::Draw` (`8218D0F8`) вычисляется смещение от выбранной клетки к
абсолютному указателю. Только вызовы DrawMatrix (`8249C430`) стрелки и её тени
с return LR `8218D69C/6FC/738/7CC/82C` временно изменяют translation матрицы
(+8/+14). Рамка, клетка и призрак растения сохраняют игровую позицию.

`TodStringListFind` (`82284C60`) возвращает копию локализованной строки.
Платформенные изменения применяются к ней через UTF-16 assign `821258D8`,
таблица строк остаётся исходной. ADVICE сохраняются в MessageWidget исходными
и адаптируются только при Draw, чтобы переключение на геймпад не оставляло
инструкции мыши. `TodDrawStringWrapped` (`82285B70`) с caller LR `821AB0B0`
смещает только текст Дэйва, затем восстанавливает Rect.

SettingsDialog::SliderVal (`82199968`, this=dialog+1C0) вызывает SetSfxVolume
(`82477778`) и Rehook (`8227FE30`). После изменения громкости проверяется
FModMusicInterface::IsPlaying (`82558978`) для song 1, только в Menu, при
активной теме 7, отсутствии паузы и положительной MusicVolume. Если голос
потерян, native Music::PlayMusic (`821C7E10`, app+A10) восстанавливает тему
и параметры инструмента. Простой FModMusicInterface::PlayMusic недостаточен:
он пропускает SetupMusicFileForTune. Прогон с искусственно потерянным каналом
подтвердил восстановление PCM; исходный сбой после Sound Effects в чистом
профиле и копии текущего профиля не воспроизвёлся.

Аудит PTX требует TranslateVirtual для данных из области Fxxxxxxx: Windows
4K physical mapping имеет host offset +1000. Прямое base+guest_address давало
ложно повреждённый дамп. Проверенный IMAGE_SEEDS: 450×70, stride 2048, DXT5,
IMAGE_SEEDPACKET_LARGER: 98×134, stride 512. Сам атлас не повреждён.
Артефакт повторился при проверке: на правом краю обычной карточки появились
полосы, тогда как растение на поле и исходные PTX остались чистыми.
`ReanimatorCache::DrawCachedPlant` (`821DEFC0`, seed=0, variation=0) теперь
вызывает native `DrawReanimatorFrame` (`821DE058`) для `anim_idle` и
`anim_head_idle` с исходными координатами и Graphics. Это устранило полосы
без замены ресурсов. Точная причина повреждения GPU-кэша не установлена.
Диагностический `pvz_peashooter_direct_draw=false` возвращает исходный путь.

### Нажатия, навигация и замечания о VSync

MainMenu теперь получает GameButton::GamepadButtonDown/Up (`824AE388` /
`824AE488`), а не прямой ButtonDepress. Draw (`82188310`) учитывает mIsDown
`+74` совместно с mIsOver `+75`; отпускание вне кнопки и смена владельца
ввода сбрасывают удержание.

`BridgeMnkDriver` заменяет только input listener исходного MnK драйвера.
Keyboard events и физические контроллеры сохраняют штатный маршрут.
LMB/RMB и относительное движение поступают MnK только при выключенном
абсолютном мостике. Release всегда очищает возможное старое удержание.
При запуске абсолютной мыши относительный mouse look отключается.
Дополнительно Coin::Collect в PC фильтрует оба native auto-collect callers:
`8218C1C4` и `821922F8`. Ручной сбор и другие игроки/режимы сохраняются.

SeedPacket::MouseDown играет SOUND_SEEDLIFT (`82D0A630`) на пути переноса
карточки в игровой курсор, caller LR `82210034`. При мыши в одиночном
Adventure этот повторный вызов LawnApp::PlaySample (`821ABDE8`) подавляется:
мостик уже проиграл звук при выборе пакета. Звуки посадки и buzzer остаются.

Menu и Back создаются через MakeDialogButton (`82188F80`) с native no-op
ButtonListener vtable `820BB39C`. Menu вызывает Board button Start (5).
Оба экрана справки используют HelpImageApplet vtable `820BB22C`; Back/ПКМ
вызывают его штатный B handler `8219A210`. HelpButtonWidget располагается
выше Help в дереве, поэтому для попаданий нужен поиск живого Help виджета.
ImageApplet::RemovedFromManager (`8219A2F0`) сам удаляет детей и передаёт
их в SafeDelete: нельзя уничтожать кнопку внутри этого callback. Listener
освобождается после настоящего GameButton destructor (`82187F70`).

Dialog::MouseDrag (`824A85F0`) ограничивал перемещение областью 800×600.
При мыши новые границы native coordinates: X -240..1040, Y -60..660;
MapUiPointer покрывает эту область, а MapBoardPointer сохраняет строгие
границы газона. Перемещение вызывает штатный virtual Move `+80`.
DrawTools (`82143880`) отдельно рисует SHOVELBANK и SHOVEL; подавлен только
DrawImage caller LR `82143B28` при выбранной лопате в PC. Поэтому пустой
лоток сохраняет исходную текстуру, а лопата курсора не исчезает.

SDK D3D12 presenter вызывает Present с SyncInterval=0 и DO_NOT_WAIT.
При запрещённом tearing композиция всё равно может ждать экран, а SDK
не отмечает этот путь как implicit-vsync. VSync теперь устанавливает
`host_present_from_non_ui_thread=false` перед переподключением presenter;
ожидание переносится на UI thread с объединением запросов новых кадров.
VSync Off возвращает flag=true и разрешает tearing. Изменения внесены
через public SDK API; SDK и частота guest simulation не изменены.
Переключение режима проверяется отдельно от субъективной оценки плавности.
