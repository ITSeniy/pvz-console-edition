# T03 — опись хуков и guest-адресов

## 1. Итог

Подготовлена воспроизводимая опись: **128 хуков**, **227 уникальных guest-функций**,
места использования адресов, обращений к памяти и пять настроек codegen. Каждый хук
отнесён к подсистеме, снабжён исходной строкой, способом вызова оригинала и ссылками
на документацию. Игра и `src/` не менялись; результат готов к отдельной приёмке.

T01 ещё не принята независимым проверяющим, поэтому её имена не использованы.
`source_name` — только комментарий из исходника, явно помеченный как непроверенный.

## 2. Изменённые файлы

- `scripts/inventory_port_hooks.py` — маскирует строки/комментарии C++, извлекает
  точки вмешательства и следует путям if/else/return для вызова оригинала.
- `docs/native-port/data/hook-inventory.csv` — все 2839 мест использования с типом записи,

- `docs/native-port/hook-inventory.md` — сводка, все 128 хуков, список обходящих оригинал,
  ограничения анализа и SHA-256 всех входов.
- `docs/native-port/reports/T03.md` — этот отчёт.

Файлы T01 в том же рабочем дереве относятся к предыдущей задаче, а не к T03.
Не создавались коммиты/ветки, `src/`, игровые образы и SDK не изменялись.

## 3. Как воспроизвести

```powershell
python -I scripts/inventory_port_hooks.py --self-test
python -I scripts/inventory_port_hooks.py --check

# Независимый подсчёт средствами rg, без анализатора:
$hookCounts = rg -c 'REX_HOOK_RAW\s*\(' src -g '*.cpp' -g '*.h'
($hookCounts | ForEach-Object { [int]($_ -split ':')[-1] } | Measure-Object -Sum).Sum

# Проверка детерминизма без удаления исходной описи:
python -I scripts/inventory_port_hooks.py --check --csv "$env:TEMP/pvz-hook-repeat.csv" --markdown "$env:TEMP/pvz-hook-repeat.md"
Get-FileHash docs/native-port/data/hook-inventory.csv -Algorithm SHA256
Get-FileHash "$env:TEMP/pvz-hook-repeat.csv" -Algorithm SHA256
Get-FileHash docs/native-port/hook-inventory.md -Algorithm SHA256
Get-FileHash "$env:TEMP/pvz-hook-repeat.md" -Algorithm SHA256

.\build.bat test
```

CSV имеет поле `kind`: `hook`, `guest-symbol`, `guest-address`, `memory-access`,
`analysis-config`. Это места использования, не число уникальных адресов/полей.
Обращения `sub_X(ctx, base)`, `__imp__sub_X`, объявления и передача указателей
различаются в `expression`; поэтому объявление `REX_EXTERN` не выдается за вызов.

SHA-256 входов: 91 файл (исходники/заголовки, существующие корневые docs/*.md,
config/analysis.toml, локальный SDK hook.h и сам анализатор). Полный манифест — в конце
`hook-inventory.md`; каждая строка CSV ссылается на его SHA-256.

Вызов оригинала: **77 always**, **42 conditional**, **9 never**. Полностью обходят
рекомпилированный оригинал семь camera-совместимых заглушек, SDK audio submission
и открытие host Achievements (`sub_822CA128`). Audio submission передаёт кадр в
`AudioSystem::SubmitFrame`; отсутствие `__imp__sub` не означает отсутствия звука.

Классификация основана на теле функции. Например, два Almanac-хука передают
`__imp__sub_82123220`/`__imp__sub_82123CD8` в `DrawAlmanacGrid` параметром `draw`;
helper вызывает `draw` и на раннем выходе, и на обычном пути. Поэтому `always`,
хотя прямого вызова `__imp__...(...)` в теле хука нет.

**Ограничение документации:** у 34 хуков нет прямого упоминания символа/адреса или
имени исходного файла в существующих корневых docs/*.md. Они описаны в новой описи;
это явно отличается от ссылки на старый документ. Наличие имени исходного файла
в документе тоже не доказывает описание всех ветвей конкретного хука.

## 6. Не проверено и риски

- Это инвентаризация исходников, не запуск каждого пути. `always` означает все
  разобранные обычные пути функции; исключения из вызываемых API/аварии не моделируются.
- Циклы/switch анализируются консервативно: ноль/одно выполнение. Такие места
  перечислены в `flow_overapproximation`; повторения и невыполнимые условия могут
  завышать набор путей. Текущие два helper-перехода разобраны отдельно и проверены.
- `original_position` — положение относительно остального текста тела, включая
  подготовку/сохранение аргументов, а не утверждение о порядке всех побочных эффектов
  из других функций. Точные строки вызовов приведены в `original_evidence`.
- Опись адресов/полей синтаксическая. Алиасы указателей, вычисляемые целиком адреса,
  косвенные вызовы через vtable и семантика классов требуют дальнейшего анализа.
- Имена в комментариях могут быть ошибочны (T01 уже выявила такие случаи); T03 их
  не исправляет и не выдаёт за доказанные Android↔Xbox соответствия.
- Независимая приёмка ещё не проведена; статус README не изменён.
