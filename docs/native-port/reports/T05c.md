### Реализация и делегирование

Хук заменяет только CRT-thunk `82616558`, общий для вызывающего его `time32`.
Он пишет FILETIME в исходный указатель, не трогает kernel export и не меняет
его другие прямые вызовы (`82616668`, `826167D8`). Поэтому глобальные host/GPU
часы остаются прежними; связанные game-сохранения и потребности получают
один согласованный источник секунд. Формула и начало отсчёта описаны в
state-dumps.md. При пустом/неверном флаге:

```cpp
const auto& clock = DeterministicClock();
if (!clock.enabled) { __imp__sub_82616558(ctx, base); return; }
```

Единственное дополнение старого logic hook — условие учёта счётчика:
`(locked || record || DeterministicClock().enabled) && updates`. При пустом
флаге часов это прежнее условие T05b. Остальные принятые хуки не изменены;
без их флагов вызывают прежний original, как при приёмке T05b. Ошибка парсинга
оставляет часы оригинальными и выдаёт ERROR ровно при первом разборе; ноль
принимается. Автоматического включения frame replay или seed нет.

### Фиксированный seed для Feedback — предложение владельцу

Предлагается добавить в `scripts/run_feedback_regression.ps1` необязательный
параметр `-DeterministicSeed`, пустой по умолчанию, валидируемый как decimal u32.
При заданном значении передавать `--pvz_deterministic_seed=<значение>` во все
процессы выбранного набора и записывать значение в evidence manifest наряду
с EXE/исходниками/CSV/профилем. Исходное предложение для диагностики — **42**,
такой же заранее фиксированный seed, как в T05b; подбор seed по зелёному checker
не выполнялся. Старый runner пока не принимает этот параметр: это описание
предлагаемой правки, не команда к уже существующему интерфейсу.

| Сценарии | Зависимость / доказательство | Предложение |
|---|---|---|
| `vases_pc`, `vases_console` | **Проверено Xbox:** mode52, populate `8215D4E0` → weighted picker `8227AB40` → global Rand `82494380` (`8227ABC4`). Содержимое и координата packet зависят от раскладки. Именно это ломает `vases_pc_place_seed`. | seed42 для воспроизводимого исходного расследования; не обещать посадку по старой координате без проверки. |
| `begh_console`, `twist_console` | **Проверено Xbox:** init ветка21/25 `82150790..9C`, заполнение `821507E0` → `82152D18` → `82152BE0`; выбор допустимого типа через Rand по `82152D00`. | seed42; нынешние действия ищут текущую допустимую комбинацию, поэтому это не свидетельство существующего отказа checker. |
| `quarium_pc`, `quarium_console` | **Проверено Xbox:** mode24 `82150A18`, два spawn `82150A68/70` → `8215C640`; Rand по `8215C67C`, случайные координаты `8215C6BC/D0`. | seed42; проверять не только покупку, но и исходные fish states при сравнении дампов. |
| `heavy_console` | **Проверено T05b:** preview `82179590` и добавление zombie `82178100` дают кластер109 обращений MT; равенство после нормализации порядка подтверждено отдельной парой T05b. | seed42, но для полного state comparison также нужен frame-locked режим. |

Это список подтверждённых в текущей работе путей, а не исчерпывающий аудит RNG
всех режимов. Остальные игровые Feedback (`whack_pc/console`, `slot_pc/console`,
`izombie_pc`, `stars_pc`, `laststand_pc/console`, `shovel_console`) разумно включать
в ту же заранее фиксированную seed-конфигурацию при общем сравнении состояния;
для каждого не заявляется доказанный RNG-отказ его конкретного assertion.
`slot_pc/console` уже используют `fixture_slot_seed`, динамические Begh/Twist
ищут допустимую комбинацию, `scrollbar` проверяет UI. Менять их ожидаемый
результат или считать отказ «исправленным seed42» без запуска нельзя.

**Seed сам по себе не гарантирует равенства:** порядок потребления RNG может
зависеть от отрисовки и seconds-replay. Принятый T05b уже показал такую причину.
После решения владельца изменение runner должно включать два повторения на
новых копиях профиля, фиксацию seed в манифесте и проверку раскладки до pickup.
Если при заранее выбранном seed нужного packet в прежней координате нет,
надо отдельно поставить корректную воспроизводимую фикстуру/доставку input,
а не менять checker или выбирать seed под исход. В этой задаче runner/CSV/
checker не правились и новый полный Feedback не объявляется пройденным.

## 5. Критерии приёмки

- Источник времени Zen подтверждён адресами: **выполнен**, таблица PPC выше.
- Zen-пара побайтно равна на всём окне5000 либо следующее расхождение с адресом:
  **выполнен равенством**, 5000/5000, zero differences, одинаковые сырые SHA.
- Без флагов поведение прежнее: **выполнен в границах изменения**, новый hook
  делегирует original, старые hooks не изменены; actual-source checks и CTest
  зелёные. Полная матрица обычных регрессий повторно не запускалась.
- Список RNG-сценариев с предложенным seed: **выполнен**, подтверждённые пути,
  кандидаты и ограничения отделены; runner не менялся.

## 6. Не проверено и риски

Проверен один epoch/seed/профиль и заданное окно, а не полный игровой день,
переход суток/часового пояса, chocolate/многочасовые потребности, все режимы и
все локальные RNG. При исходном профиле из будущего относительно epoch логика
так же увидит будущее: timestamps не переписываются. Флаг не включает и не
нормализует прямые обращения других функций к kernel time. Это граница CRT
времени игры, не универсальная виртуализация системных часов.

Проекция state dump ограничена T05: равенство не означает побайтного равенства
всей guest memory, GPU, audio или UI. Диагностические преобразования T05b
сохраняются со своими ограничениями. Проверки с отрицательным/повреждённым
флагом используют локальный harness, а не ещё восемь игровых запусков.

Сохранить следующий текст как `runtime-data/t05c/run-zen.ps1`. Он не заменяет
штатные scripts/run_* и не меняет их.

<!-- T05C_RUNNER_BEGIN -->
