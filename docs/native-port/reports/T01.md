# T01 — карта имён Xbox ↔ Android

## 1. Итог

Доработан анализатор, подготовлен консервативный экспорт из **133 имён: 6 high и 127
medium**. На ручном контрольном наборе из 49 функций: high 6/6, medium 23/23; ещё
19 предсказаний имеют low, одна функция намеренно не определяется. Это результат
исполнения, готовый к отдельной приёмке, а не изменение статуса в README.

Результат не меняет игру. В частности, обнаруженные неправильные комментарии в `src/`
оставлены для T02. Совпадение имени/сигнатуры Android не доказывает идентичность ABI Xbox.

## 2. Изменённые файлы

- `scripts/name_xbox_from_android.py` — изолированный запуск, точнее извлечение строк,
  два независимых выравнивания, проверка контрольного набора, CSV и диагностический
  дизассемблер `--inspect`.
- `research/cross-platform/xbox-android-names.json` — полный пересоздаваемый вывод;
  исключён из git существующими правилами.
- `docs/native-port/data/xbox-names.csv` — только high/medium, требуемые семь колонок.
  В `evidence` — признаки, SHA-256 обоих бинарников и SHA-256 полного манифеста входов,
  который находится в JSON. CSV и JSON образуют одну поставку.
- `docs/native-port/data/name-map-golden.json` — 49 вручную размеченных функций,
  Xbox-инструкции/константы и адреса ARM для повторной проверки; три отрицательных случая.
- `docs/native-port/reports/T01.md` — этот отчёт.

До работы уже существовали неотслеживаемые `docs/native-port/`, feasibility-документ
и черновик анализатора. Ветки, коммиты, `generated/`, `.cache/`, образы и игровой код
не изменялись.

## 3. Как воспроизвести

Из корня проекта:

```powershell
python -I scripts/name_xbox_from_android.py --quiet --check
Get-FileHash research/cross-platform/xbox-android-names.json -Algorithm SHA256
Get-FileHash docs/native-port/data/xbox-names.csv -Algorithm SHA256

# Другие имена выходов позволяют сравнить два прогона без удаления результатов.
python -I scripts/name_xbox_from_android.py --quiet --check --output "$env:TEMP/pvz-t01-repeat.json" --csv "$env:TEMP/pvz-t01-repeat.csv"
Get-FileHash "$env:TEMP/pvz-t01-repeat.json" -Algorithm SHA256
Get-FileHash "$env:TEMP/pvz-t01-repeat.csv" -Algorithm SHA256

# Пример независимой проверки Xbox и ARM, без записи файлов:
python -I scripts/name_xbox_from_android.py --inspect 82473000 --android 3af2ac
python -I scripts/name_xbox_from_android.py --inspect 82190d80 --android 1bce78
python -I scripts/name_xbox_from_android.py --inspect 824bfd18 --android 32f010

.\build.bat test
```

`--check` завершает процесс с ненулевым кодом, если high <100%, medium <90% на
контрольном наборе, набор меньше 40 записей, провален отрицательный случай, есть
противоречащие строки high или нарушены восемь контрольных слотов ввода Widget.
Отсутствие контрольного набора не считается успехом.

В JSON хешируются **все 70 входных файлов**, включая оба бинарника, таблицу символов,
заголовок стартов функций, все читаемые `src/*.cpp`/`src/*.h`, необязательную таблицу
challenge, golden и оба Python-скрипта. Обогащённая Android-таблица сверяется с ELF
по name/value/size/type/binding/section для каждого символа, а не только по длине.

## 4. Результаты и доказательства

### Что было неправильно в методе

**Проверено по коду анализатора и бинарникам:**

1. Сумма сходства размеров, числа вызовов и пустых тел объявлялась high. Это признаки
   для поиска кандидата, но не независимые доказательства смысла функции. Теперь такие
   кандидаты остаются low, включая унаследованные/синтезированные имена.
2. У ResourceManager разные виртуальные интерфейсы (22 Xbox-слота против 34 Android).
   Последовательное выравнивание сдвигало GetSound/GetFont на RenderEffect/GenericResFile.
   Уникальные диагностические строки теперь ограничивают выравнивание всего интерфейса.
3. Собственная строка функции могла бы одновременно определять слот и подтверждать его.
   Для high учитывается только совпадение **второго выравнивания без строк** либо порядок
   не менее двух разных независимо названных callees. Повышения не распространяются
   рекурсивно. Пороги приёмки 100%/90% сохранены.
4. Глобально уникальные `NULL`, `File`, `TITLE` сопоставляли несвязанные подсистемы.
   Короткие токены исключены. Диагностика FMOD против Android `dumb_*` — конфликт
   аудиобэкендов, а не соответствие функций по заголовку XM `Extended Module:`.
5. PPC-экстрактор хранил `lis` после перезаписи регистра/перехода и перепутывал операнды
   `ori`. Теперь учитываются источник RS, назначение RA, нулевая база `addi`, убийство
   определений на ветвлениях/вызовах/перезаписи. ARM учитывает `regs_access` и не переносит
   литералы через ветвления/вызовы. Это намеренно неполный straight-line анализ.
6. Шаблонные MSVC RTTI остаются непрозрачными, явно вынесены в `excluded_xbox_classes`
   вместе со `std::`. Искажённых псевдоимён `std::::...` в карте классов больше нет.
7. Проверка якорей раньше молча пропускала адреса без предсказания. Теперь перечисляет
   все **129** найденных исходных комментариев. Число 21 в карточке — пересечение
   комментариев со старым черновиком, а не полный набор комментариев проекта.

## 5. Критерии приёмки

- **Выполнен:** разобраны все исходные 21; таблица выше и адресная доказательная база golden.
- **Выполнен:** high=100%, medium≥90% на golden; `validation.golden` считает 6/6 и 23/23.
- **Выполнен:** ни одного строкового противоречия high; все шесть имеют общие строки.
- **Выполнен:** 133 экспортируемых имени; JSON summary и число записей CSV совпадают.
- **Выполнен:** два изолированных процесса дают побайтно одинаковые JSON и CSV.
- **Выполнен:** JSON содержит SHA-256 каждого читаемого входа; CSV ссылается на тот же
  манифест SHA-256 и содержит хеши образов непосредственно в evidence.

## 6. Не проверено и риски

- Приёмка другим исполнителем ещё не проводилась; README не изменён.
- Покрытие снижено намеренно: необоснованные 440 high старого черновика не сохранены.
  Нет обещания одинаковых тел функций, ABI, раскладок полей или поведения игры.
- У функций без символов Xbox нельзя восстановить точную C++-сигнатуру только по
  Android. Например, дополнительный аргумент GetFontThrow и аргумент UpdateCrow требуют
  отдельного ABI-анализа перед нативной заменой.
- Размер Xbox — интервал до следующего старта из codegen, включая возможное выравнивание,
  а не гарантированная длина всех достижимых инструкций.
- Дизассемблер может показывать literal pools Thumb как инструкции. Непрерывные цепочки
  и указатели строк проверялись отдельно; автоматическое отсутствие строки не доказывает
  отсутствия её использования.
- Живые сценарии игры не запускались: T01 меняет только инструменты/таблицы, а не runtime.

остаются открытыми решениями из README; для этой работы они не нужны.

## Проверки исполнителя перед приёмкой

- `build.bat test`: **10/10 passed**.
- Семь синтетических PPC-примеров: lis/addi, перезапись, call, conditional branch, ori,
  нулевая база r0, уничтожение старого lis при addi — **7/7**. Проверялись временным
  harness вне проекта; он не является постоянным тестом репозитория.
- High проверены все шесть (популяция меньше требуемой выборки 20). Medium: seed
  **20261016**, исходная выборка 20; найден один ложный межбэкендный XM-кандидат FMOD/DUMB,
  исправлено правило несовместимости бэкендов, случай сохранён отрицательным контролем.
  Остальные 19 подтверждены по PPC/Thumb, константам и роли операций; входят в golden.
- После фикса все 49 golden-записей пересчитаны, исходные 21 проверены отдельно.
- Преднамеренно испорчен expected name Board::Draw в **временной копии** golden:
  `--check` завершился кодом **1**, high стал **5/6**. Массив `functions` в JSON при этом
  побайтно эквивалентен обычному прогону: golden не влияет на предсказания.
- Два запуска с неизменными входами: JSON и CSV побайтно совпадают; точные текущие
  хеши воспроизводятся командами раздела 3.

Это самопроверка исполнителя. Решение независимой приёмки и статус задачи не подменяются.

## Приёмка (17.10.2026)

**Итог: принято с замечаниями.** Точность экспортированных имён подтверждена, но покрытие
слишком узкое для T02, T04 и T07.
