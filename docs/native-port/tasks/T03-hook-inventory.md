# T03. Опись хуков и guest-адресов порта

**Этап:** знание · **Зависит от:** — (имена из T01 добавить, когда она будет принята) · **Объём:** средний · **Меняет поведение игры:** нет

## Цель

Полная карта того, где порт вмешивается в игру. Она нужна, чтобы планировать нативные
замены по подсистемам и видеть, какие хуки исчезнут при переписывании функции.

## Входы

`src/*.cpp`, `src/*.h` (128 `REX_HOOK_RAW`, 227 уникальных `sub_XXXXXXXX`, смещения в
`guest_layout.h`, `board_mapping.h`, `menu_mapping.h` и др.), `config/analysis.toml`,
`docs/*.md` с описаниями хуков.

## Что сделать

1. `scripts/inventory_port_hooks.py`: найти все
   - `REX_HOOK_RAW(...)` и прочие макросы хуков из `research/rexglue-source/include/rex/hook.h`;
   - вызовы guest-функций (`sub_X(ctx, base)`, `__imp__sub_X`);
   - константы guest-адресов (`0x82xxxxxx`) и смещения полей, используемые при чтении памяти;
   - записи `config/analysis.toml`.
2. Для каждого хука определить: файл и строку, вызывает ли оригинал (до, после, условно,
   никогда), подсистему (ввод, меню, рендер, звук, сохранение, платформа…), документ в `docs/`,
   где он описан.
3. Если T01 уже принята — колонка с именем и уверенностью; иначе — комментарий из исходника.

## Результат

`scripts/inventory_port_hooks.py`, `docs/native-port/data/hook-inventory.csv`,
`docs/native-port/hook-inventory.md` (сводка по подсистемам: сколько хуков, какие функции,
какие полностью заменяют оригинал), `docs/native-port/reports/T03.md`.

## Критерии приёмки

- [ ] Число найденных `REX_HOOK_RAW` совпадает с `grep -c` (сверка в отчёте).
- [ ] Каждый хук отнесён к подсистеме; категория «прочее» — не больше 10 %.
- [ ] Поле «вызывает оригинал» заполнено по коду, а не по названию. Выборка из 10 случайных строк проверена вручную.
- [ ] Скрипт пересоздаёт CSV один в один.

## Вне рамок

Любые правки `src/`.
