# T05b. Детерминированный диагностический режим реплея

**Этап:** инструменты проверки · **Зависит от:** T05 (инструменты приняты) · **Объём:** средний · **Меняет поведение игры:** только под флагом

## Цель

T05 показала: два прогона одного реплея расходятся с кадра 0 (`rng_hash`). Без
детерминизма снимки T05 не могут доказать эквивалентность нативной замены (T06). Нужен
режим, в котором два прогона дают одинаковые снимки хотя бы на игровых сценариях.

## Известные источники недетерминизма (проверено при приёмке T05)

1. **Seed RNG.** Инициализация приложения `82482080..88` вызывает `822CA100`. Тот читает
   `KeTimeStampBundle` (импорт `82000850`, поле `+10`), а результат уходит в seed wrapper
   `824943A0`. В ReXGlue это `QueryGuestUptimeMillis()`.
2. **Доставка ввода по времени.** `StartInputReplay` (`src/input_replay.cpp`) работает в
   отдельном `std::jthread` по `steady_clock` с опросом 25 мс. События не привязаны к номеру
   логического шага.
3. Возможны другие: переменный `dt` в обновлении, порядок загрузки ресурсов, звук. Их нужно
   выявить, а не предполагать.

## Что сделать

1. Флаг `--pvz_deterministic_seed=<u32>`: подменить значение, которое получает seed wrapper
   (`824943A0` или вызов `822CA100` из `82482080`). `KeTimeStampBundle` глобально не менять:
   он нужен и другим подсистемам.
2. Флаг `--pvz_replay_frame_locked=true`: реплей с колонкой «номер логического шага»
   вместо секунд. Событие подаётся ровно на нужном шаге из хука `sub_82492618` (T05) или
   точки опроса ввода. Конвертер `scripts/replay_seconds_to_steps.py` переводит существующие
   CSV по записанному прогону. Старый формат должен работать как раньше.
3. Если игра считает `dt` по реальному времени, найти это место и под тем же флагом
   зафиксировать шаг (например, ровно 1/100 с). Обосновать адресом.
4. Повторить таблицу детерминизма T05 на тех же пяти сценариях в новом режиме. Для каждого
   оставшегося расхождения — кадр, поле и найденная (или ненайденная) причина.

`src/deterministic_replay.cpp` (+ `CMakeLists.txt`), правки `src/input_replay.cpp` строго

## Критерии приёмки

- [ ] Без новых флагов поведение прежнее: `.\build.bat test` и все четыре набора регрессий
      проходят без изменения реплеев и проверяющих скриптов.
- [ ] В новом режиме минимум Adventure, Versus и одна мини-игра дают **побайтно одинаковые**
      снимки в двух отдельных процессах на всём записанном окне.
- [ ] Чувствительность T05 (+1 солнце на кадре N) по-прежнему ловится на кадре N.
- [ ] Каждое оставшееся расхождение описано с адресом источника или явно помечено «причина не найдена».
