# T05. Снимки состояния и сравнение реплеев

**Этап:** инструменты проверки · **Зависит от:** — · **Объём:** средний · **Меняет поведение игры:** нет (только диагностика под флагом)

## Цель

Возможность доказать, что нативная замена функции не меняет игру: прогнать один реплей
дважды (оригинал и замена) и сравнить состояние игры покадрово. Сначала — выяснить,
детерминирован ли реплей сам по себе.

## Входы

Реплеи `tests/replays/*.csv`, `--pvz_input_replay`, `smoke.ps1`, известные адреса
(`src/guest_layout.h`, `board_mapping.h`), фикстуры уровней (`src/replay_fixtures.cpp`).

## Что сделать

1. Флаг `--pvz_state_dump=<file>`: каждый игровой кадр (`Board::Update` или ближайшая точка,
   уже используемая портом) писать компактную запись — номер кадра, режим, солнце, число и
   хеш активных растений, зомби, снарядов, монет (тип, позиция, здоровье), состояние RNG, если
   найдётся. Формат — JSON Lines или CSV. Без флага код не выполняется.
2. `scripts/compare_state_dumps.py a b`: первое расходящееся поле и кадр, сводка.
3. Проверка детерминизма: каждый из 5 реплеев (уровень Adventure, Versus/Co-op, одна
   мини-игра, Zen Garden, меню) прогнать дважды без изменений. Если расходится, найти
   источник (время, RNG от часов, порядок потоков) и описать; лечить только через
   диагностический флаг (например, фиксированный seed), не меняя поведение по умолчанию.
4. Проверка чувствительности: под временным флагом изменить одно значение (например, +1
   солнце на кадре N) и убедиться, что сравнение показывает кадр N.

## Результат

Правки в одном новом файле `src/state_dump.cpp` (+ регистрация в `CMakeLists.txt`),
`scripts/compare_state_dumps.py`, `scripts/run_determinism_check.ps1`,
`docs/native-port/state-dumps.md` (как пользоваться), `docs/native-port/reports/T05.md`.

## Критерии приёмки

- [ ] Без `--pvz_state_dump` игра ведёт себя как раньше: регрессии из `scripts/run_*_regression.ps1` проходят.
- [ ] Таблица детерминизма по 5 реплеям: совпало / разошлось на кадре N / причина.
- [ ] Проверка чувствительности ловит искусственное изменение на нужном кадре.
- [ ] Накладные расходы флага измерены (время кадра с флагом и без).

## Вне рамок

Нативные замены функций (T06); исправление недетерминизма в обычном режиме.
