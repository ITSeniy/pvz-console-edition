# T11. Разметка функций Xbox по классам и план пакетов замен

**Этап:** знание · **Зависит от:** T01, T01b, T02, T03 (приняты) · **Объём:** средний · **Меняет поведение игры:** нет

## Цель

Дальше нативные замены идут пакетами по подсистемам, а не по одной функции. Для
планирования нужно знать, какому классу принадлежит каждая функция Xbox, сколько в
классе кода и что о нём уже известно. Сейчас именованы 150 функций из примерно 21 000.

## Что сделать

1. **Области кода.** Разметить все функции из `generated/default/pvz_funcs.h` по областям:
   - игра `0x82120000–0x822B0000`;
   - платформа Xbox `0x822B0000–0x82300000`;
   - middleware `0x82300000–0x82470000` (FMOD, FEAST, libpng, JPEG, zlib, GIF, XUI);
   - Sexy `0x82470000–0x825B0000`;
   - CRT/XDK от `0x825B0000`.

   Границы проверить по коду и строкам, уточнить в отчёте с доказательствами.
2. **Класс каждой функции.** Для функций игры и Sexy установить класс и, где можно, метод.
   Признаки по убыванию силы:
   - слот vtable класса с известным именем (T01/T01b, `android-symbols.json`);
   - принятое имя из `docs/native-port/data/xbox-names.csv`;
   - запись vtable в конструкторе и распространение типа `this`: функция получает в `r3`
     объект класса, установленный по vtable или полю известной раскладки T04;
   - уникальные строки и константы, общие с Android/PC;
   - вызов только из методов одного класса — слабый признак, только low.

   Уровни high, medium, low — по правилам `agent-guide.md`. Функции без признака оставить
   `unknown`, не угадывать.
3. **Сопоставление с PC.** Для класса указать, есть ли он в `research/pvz-pc/` (файл), и для
   метода — есть ли одноимённая функция. Это факт наличия, не перенос кода.
4. **Связь с портом.** По `docs/native-port/data/hook-inventory.csv` отметить функции, на
   которые уже есть хуки порта.
5. **Сводка и план пакетов.**
   - Таблица по классам: число функций, байты, сколько с именем, сколько с PC-аналогом,
     сколько с хуками порта, главные вызывающие и вызываемые классы.
   - Предложить разбиение игрового кода и Sexy на 25–30 пакетов замен с порядком. Опора:
     зависимости по вызовам (сначала листовые помощники), наличие PC-аналога, связь с
     известными проблемами порта, риск (рендер, платформа, звук — в конце).
   - Для каждого пакета: функции, байты, зависимости, что проверять.
6. **Воспроизводимость.** Скрипт строит таблицу из входов без ручных правок и записывает
   SHA входов.

## Критерии приёмки

- [ ] Каждая функция из `pvz_funcs.h` ровно в одной строке CSV с областью; суммы по
      областям сходятся с общим числом функций и байт.
- [ ] Выборочная проверка по `review.md`: 20 случайных отнесений high — 0 ошибок;
      20 medium — не больше 2. Seed выборки указан, проверяющий повторяет её.
- [ ] Ни одно отнесение не опирается только на Android/PC без признака в Xbox-коде.
- [ ] Повторный запуск скрипта на тех же входах даёт побайтно тот же CSV.
- [ ] План пакетов покрывает игровой код и Sexy без пересечений. Для каждого пакета
      указаны зависимости, и порядок их не нарушает (кроме явно названных циклов).
