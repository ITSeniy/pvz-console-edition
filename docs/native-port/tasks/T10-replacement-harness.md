# T10. Общий механизм нативных замен и доказательство одной командой

**Этап:** инструменты проверки · **Зависит от:** T05b, T05c, T06 (приняты и перенесены) · **Объём:** средний · **Меняет поведение игры:** нет (только под флагами)

## Цель

T06 доказала одну замену вручную: флаги, режим сравнения, журнал, пять сценариев снимков
и отрицательный контроль. Следующие замены пойдут пакетами по десяткам функций, и ручной
цикл станет узким местом. Нужен общий механизм: объявить замену в несколько строк, а
доказательство получить одной командой с машинно-проверяемым итогом.

## Что сделать

1. **Механизм (`src/native/replacement.h`, при необходимости `.cpp`).** Одно объявление
   замены создаёт:
   - флаги `pvz_native_<name>`, `pvz_native_<name>_compare` и
     `pvz_native_<name>_inject_error` (последний действует только вместе с compare);
   - общий флаг `--pvz_native_compare_all=true`, который включает compare для всех
     зарегистрированных замен;
   - путь без флагов: одна проверка статического bool, затем `__imp__` и возврат;
   - сравнение объявленных выходов:
     - уровень 1 — регистры: перечень GPR/FPR, ширина и знаковость;
     - уровень 2 — guest-память: перечень диапазонов, вычисляемых из аргументов.
       Механизм сохраняет диапазоны до вызова, выполняет native и сохраняет результат.
       Затем восстанавливает исходные байты, выполняет оригинал и сравнивает. В реальной
       игре остаётся результат выбранной версии.
   - учёт и журнал: каждое расхождение с аргументами — всегда. Сводка (число сравнений и
     ошибок) — периодически, не реже раза в 1000 вызовов и в конце реплея, чтобы оборванный
     процесс давал точные счётчики без записи каждого вызова.

   Замена с побочными эффектами вне объявленных выходов в compare не допускается. Это
   требование к объявлению, проверяется в отчёте по телу Xbox. Предусмотреть явный признак
   «только снимки, без compare» для таких функций в будущем.
2. **Перевод пилота.** `src/native/pixel_to_grid_x.cpp` перевести на механизм. Имена
   флагов и смысл режимов сохранить. На тех же сценариях число сравнений и расхождений
   должно совпасть с отчётом T06.
3. **Второй пилот — выход через память.** Выбрать одну функцию с именем из
   `src/xbox_names.h` или с доказанным в отчёте именем, которая пишет результат в память по
   указателю (например, прямоугольник объекта), без других побочных эффектов. Обосновать
   выбор по телу Xbox и ABI. Реализовать на уровне 2.
4. **Прогон доказательства (`scripts/run_native_proof.ps1`).** Одна команда для одной или
   нескольких замен:
   - compare-прогон на пяти сценариях T05b/T05c (выбран оригинал): сравнения и ошибки по
     каждой замене и сценарию;
   - отрицательный контроль с `inject_error` для каждой замены: ошибка должна быть поймана;
   - снимки состояния original/native на пяти сценариях через `compare_state_dumps.py`;
   - снимки «оригинал без флагов» против «compare с выбранным оригиналом»: доказательство,
     что восстановление памяти на уровне 2 ничего не меняет;
   - `summary.json` и `summary.md` с SHA входов, командами, счётчиками и итогом по каждому
     критерию. Код выхода ненулевой при любом провале или нулевом охвате замены.

   `scripts/run_determinism_check.ps1` использовать повторно. Если нужен параметр для
   дополнительных флагов игры, добавить его без изменения поведения по умолчанию.
5. **CTest.** Тест механизма без игры, на поддельном `PPCContext` и буфере памяти:
   - сравнение регистров и памяти;
   - восстановление байтов после native;
   - срабатывание `inject_error`;
   - путь без флагов не трогает память.

   Самопроверка разбора журнала для `run_native_proof` — тоже в CTest.
6. **Шаблон.** Обновить `docs/native-port/replacement-howto.md` под новый механизм: что
   объявить, что доказать по телу Xbox, какую команду запустить, что приложить к отчёту.

## Критерии приёмки

- [ ] PixelToGridX на новом механизме: флаги прежние, на тех же сценариях счётчики сравнений
      равны T06, расхождений 0, `inject_error` ловится.
- [ ] Второй пилот: не меньше 10 000 реальных сравнений (или явно указан меньший охват с
      причиной), 0 расхождений, `inject_error` ловится. Выходы через память сравниваются
      побайтно.
- [ ] Восстановление памяти доказано: снимки «без флагов» и «compare, выбран оригинал»
      совпадают на всех пяти сценариях.
- [ ] Снимки original/native совпадают на всех пяти сценариях для обеих замен.
- [ ] `run_native_proof.ps1` повторно на том же EXE даёт те же счётчики и тот же итог; при
      намеренно сломанной замене завершается с ошибкой.
- [ ] Без флагов поведение прежнее: `.\build.bat test` проходит, штатные регрессии — как
      базовый прогон (известные нестабильные `pc_settings_back` без `pvz_gamepad_repeat_fix`
      и `vases_pc_*` отделить контрольным прогоном, ожидания не менять).
