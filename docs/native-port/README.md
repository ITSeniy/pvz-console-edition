# Нативный порт: план работ для агентов

Здесь собраны задачи гибридного перехода от рекомпиляции ReXGlue к нативному коду.
Задачи выполняют отдельные агенты; результат каждой проверяется до принятия.
Обоснование выбора — [native-port-feasibility.md](../native-port-feasibility.md).

| Документ | Для кого |
|---|---|
| [agent-guide.md](agent-guide.md) | Агент-исполнитель: правила, источники, ограничения, формат отчёта. **Прочитать до начала любой задачи.** |
| [review.md](review.md) | Проверяющий: как принимать результат, выборочные проверки, признаки халтуры |
| `tasks/Txx-*.md` | Карточка задачи: цель, входы, результат, критерии приёмки |
| `reports/Txx.md` | Отчёт агента по задаче (создаёт агент) |
| `data/` | Небольшие итоговые таблицы, которые нужно хранить в git (`research/` в `.gitignore`) |

## Этапы

1. **Знание.** Имена функций Xbox, раскладки структур, опись хуков порта. Поведение игры
   не меняется.
2. **Инструменты проверки.** Снимки состояния игры и сравнение реплеев. Без них нативную
   замену нельзя доказать.
3. **Пилотные замены.** Одна чистая функция, затем одна подсистема с открытой проблемой.
4. **Исследования границ.** Рендер (`Sexy::Graphics`) и ассеты для пути без ReXGlue.

## Открытые решения (за владельцем проекта, не за агентами)

- **Лицензия порта.** В репозитории нет LICENSE. Мод PvZ TV Touch под GPL-3.0,
  PvZ-Portable под LGPL-3.0. Пока решения нет, код из них не копируется (см. agent-guide).
- **Переименование функций в codegen.** ReXGlue умеет `name = "..."` в `[functions]`
  (`config/analysis.toml`). Но это меняет символы `sub_XXXXXXXX`, на которые ссылаются все
  `REX_HOOK_RAW` в `src/`. До решения имена живут только в отдельном заголовке и комментариях (T02).
- **Где хранить итоговые данные.** Предложено `docs/native-port/data/` для небольших
  проверенных таблиц; крупные выводы анализаторов остаются в `research/` и воспроизводятся
  скриптами.
