# T06 — пилот нативной замены Board::PixelToGridX

## 1. Итог

Реализована замена Xbox `82149538` через `REX_HOOK_RAW`, выключенная по умолчанию.
Выбор чистого координатного метода вне текущих 150 имён отдельно разрешён владельцем
в этой сессии: «Разрешить чистую функцию координат с доказательством в T06».
`xbox_names.h` не изменён. Пять детерминированных сценариев T05b/T05c совпали
побайтно в двух видах проверки; искусственная ошибка обнаружена в живой игре.
Игровое сравнение охватило 1 855 348 вызовов без расхождений. Обычные регрессии
прошли за исключением ранее известной pc_settings_back; эта оговорка отмечена
в критериях, ожидания проверки не менялись.

Основа: отдельный worktree `t06-native-pilot`, detached HEAD
`bf63a67873304bfd0d4875d96a28cb2ebcff02c2`. Коммитов нет; статусы README не менялись.

## 4. Результаты

### 4.1. Выбор, имя и контракт — проверено по Xbox

Принятый `Zombie_ZombiquariumFindClosestBrain` не подходит как чистый пилот:
Xbox-тело не ограничивается поиском, а также съедает мозг, меняет здоровье и состояние.
Исполнять его дважды в общей guest-памяти небезопасно. Поэтому согласовано исключение
для `Board::PixelToGridX`, без изменения принятой карты имён и её уровней уверенности.

Доказательство имени: целое тело `82149538..821495A8` (29 PPC-инструкций),
а не совпадение константы или комментария. Аргументы: r3=Board*, r4=signed x,
r5=y; результат r3 — signed integer с точным 64-битным представлением PPC.

| PPC | Смысл |
|---|---|
| 82149538..82149560 | Board.app(+F4), app.game_mode(+9CC)=44 и background(+55E0) в {6,7,8} |
| 82149564..82149568 | app.field_9f0(+9F0), tail-call 82291A00 с теми же x/y |
| 8214956C..82149578 | x < 40 → -1 |
| 8214957C..821495A8 | signed (x−40)/80, clamp к 0..8 |

Форма обеих ветвей соответствует `research/pvz-pc/Lawn/Board.cpp:9013`
(`Board::PixelToGridX`, MIT), включая специальную Zen-ветвь. Xbox является
источником констант, смещений и ABI. Нативный код написан по этому PPC-разбору;
GPL/LGPL-код не переносился. Само имя подтверждено совокупностью полного алгоритма,
Zen-переадресации и координатных потребителей; записи high в карте по-прежнему нет.

Собственных игровых store, RNG, времени, выделений или доставки событий у метода
нет. `82291A00` читает координатную таблицу Zen; его scratch stack не является
постоянным состоянием. Этот дочерний метод сохранён оригинальным. Новая версия
читает поля только через принятые `pvz::xbox::Board`/`LawnApp` и endian-типы T04.

При обоих выключенных флагах хук немедленно вызывает `__imp__sub_82149538`.
Shadow-контекст копируется до оригинала; сравнивается r3.u64, возвращается выбранный
результат. Изменение volatile-регистров/scratch stack не выдаётся за различие ABI.

## 6. Не проверено и риски

- Полная ручная функциональная приёмка всех 36 Edge-Tests не проводилась.
- Zen-переадресация остаётся Xbox-функцией; это пилот одного метода.
- Живой Zen использует состояние исходного профиля; все три значения background
  специальной ветви проверены изолированно, а полный живой обход всех садов не заявляется.
- Совпадение полей T05 не доказывает равенство всех байтов guest RAM или звука.
- Shadow-режим много пишет в журнал и меняет host timing; для снимков поэтому
  использованы логические replay и детерминированные seed/часы. Native-only
  дополнительно исключает зависимость от volatile clobbers original.

## Приёмка (17.10.2026)

**Итог: принято.** Первая нативная замена работает по полному циклу T01→T04→T05b→T06.

- Независимая сверка: дизассемблер `82149538..821495A8` (Capstone по `.cache/pvz-image.bin`)
  совпадает с `Native()` по каждой ветви. `app=Board+F4`; `game_mode +9CC == 44` и
  `background +55E0` ∈ {6,8,7} → `r3 = app+9F0`, хвостовой вызов `82291A00`; `x < 40` → −1;
  иначе `divw (x−40)/80` с ограничением 0..8. Совпадает и с `research/pvz-pc/Lawn/Board.cpp`
  (`Board::PixelToGridX`, MIT).
- Без флагов хук сразу вызывает оригинал. Режим сравнения вычисляет обе версии и возвращает
  выбранную; отрицательный контроль в живой игре сработал.
- Функции нет среди 150 имён. Исключение, по словам отчёта, согласовано владельцем;
  имя подтверждено телом функции, а не одним признаком, — для пилота этого достаточно.
- Замечание: в режиме сравнения каждый вызов пишется в журнал на уровне INFO (около 1,9 млн
  строк). Для диагностики приемлемо; для следующих замен в шаблоне стоит логировать
  только расхождения и итоговый счётчик.
