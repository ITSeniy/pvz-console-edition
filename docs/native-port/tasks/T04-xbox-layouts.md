# T04. Раскладки структур Xbox с проверенными смещениями

**Этап:** знание · **Зависит от:** T01 (принятая) · **Объём:** большой · **Меняет поведение игры:** нет

## Цель

Типизированные описания ключевых классов Xbox: поля big endian, 32-битные guest-указатели,
`static_assert` на смещения. Это основа нативного кода. Ручная арифметика смещений в `src/`
со временем заменяется этими структурами (не в этой задаче).

## Классы (по приоритету)

`LawnApp`, `Board`, `GamepadControls`/`BaseGamepadControls`, `SeedBank`, `SeedPacket`,
`Plant`, `Zombie`, `Coin`, `Challenge`, `CursorObject`, `Sexy::Widget`. Достаточно полей,
которые встречаются в коде порта и в функциях с именами high. Полнота не требуется.

## Входы

Xbox-код (`generated/`, `.cache/pvz-image.bin`), имена T01, смещения из `src/guest_layout.h`
и соседних заголовков. Как подсказки: PC `research/pvz-pc/Lawn/*.h`, заголовки мода
PvZ TV Touch для Android 1.1.5 — смещения там **другие**; переносить порядок и типы полей, а
не числа.

## Что сделать

1. Для каждого поля найти в Xbox-коде хотя бы одно обращение в функции с известным именем
   и записать доказательство: `адрес инструкции — функция — смысл`. Годятся имена high и
   medium из `xbox-names.csv`, golden-наборы и имена, которые агент установит сам. Для
   собственных имён — доказательство в формате golden: строки, константы, вызовы. (Изменено
   при приёмке T01b: high всего 7.)
2. Описать поля в `src/xbox/<Class>.h` с обёрткой big endian. Проверить, есть ли готовая
   `be<T>` в `research/rexglue-source/include`, и взять её; свою — только если готовой нет.
   Пропуски — `uint8_t pad_XXX[n]`.
3. `static_assert(offsetof(...) == 0x…)` на каждое описанное поле; `sizeof` — где размер
   известен (например, из `operator new` в конструкторе или шага `DataArray`).
4. Таблица доказательств: `docs/native-port/data/xbox-layouts.csv`
   (`class,field,offset,type,evidence_address,evidence_function,confidence`).
5. Сверить с уже используемыми в `src/` смещениями; расхождения перечислить.

## Результат

`src/xbox/*.h` (новые, нигде пока не подключаются, кроме теста), `tests/xbox_layout_test.cpp`
(только `static_assert` и компиляция) и строка в `CMakeLists.txt` для теста,
`docs/native-port/data/xbox-layouts.csv`, `docs/native-port/reports/T04.md`.

## Критерии приёмки

- [ ] `.\build.bat test` проходит, новый тест в нём есть.
- [ ] У каждого поля есть доказательство из Xbox-кода; полей «по аналогии с Android/PC» без доказательства — ноль (такие помечаются как гипотезы в CSV и в заголовок не попадают).
- [ ] Все смещения, уже используемые в `src/`, либо совпадают, либо расхождение объяснено.
- [ ] Ни одной строки кода из мода PvZ TV Touch.

## Вне рамок

Перевод существующего кода порта на новые структуры — отдельная задача после приёмки.
