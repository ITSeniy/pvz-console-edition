# T14. Инструменты для пакетов: трасса отрисовки, синтетическое сравнение, журналы

**Этап:** инструменты проверки · **Зависит от:** T10, T12, T13 (приняты) · **Объём:** средний · **Меняет поведение игры:** нет (только диагностика под флагами)

## Цель

T13 показал, где у процесса пакетов пробелы:

- **Отрисовка не проверяется.** 21 из 36 включённых функций B001 проверены только снимками
  состояния, а снимки не видят отрисовку. Среди этих функций — рисующие текст.
- **Почти половина пакета без доказательства.** 31 из 68 функций не вызываются в пяти
  сценариях; 24 из них имеют объявленные выходы и могли бы сравниваться.
- **Проверка дорогая и шумная.** Отрицательный контроль пишет 232 МиБ журнала на один
  реплей, `smoke.ps1` при ротации журнала ждёт лишние 120 с, флаги пакета вписаны вручную
  в общий заголовок.

Нужно закрыть эти пробелы до следующего пакета.

## Что сделать

1. **Трасса отрисовки.** Диагностический флаг, который записывает вызовы примитивов
   `Sexy::Graphics` (вывод строк, изображений, прямоугольников, установка цвета, шрифта,
   клипа — набор определить по Xbox-коду и T08) с аргументами. Сравнение двух
   детерминированных прогонов (T12: seed, часы, пошаговые реплеи):
   - трассы двух одинаковых прогонов без замен должны совпадать. Если число кадров
     отрисовки между логическими шагами плавает, сравнивать трассу кадра, нарисованного
     после каждого логического шага, и описать правило в отчёте;
   - прогон с `--pvz_native_b001=true` против прогона без него;
   - отрицательный контроль: искусственная ошибка в рисующей замене (например, сдвиг `x` на 1
     в `Centered` под `inject_error`) должна дать расхождение с номером шага и вызовом.

   Добавить фазу в `run_native_proof.ps1` для функций `SnapshotsOnly`.
2. **Синтетическое сравнение.** Для замен `DeclaredOutputsOnly` — проверка без игрового
   сценария: обе версии (native и исходная generated-функция) вызываются на наборе входов в
   изолированной guest-памяти, выходы сравниваются побайтно. Как в T10 для `tool_rect`
   (31 104 случая).
   - Входы описываются при объявлении замены: регистры, поля объекта по раскладкам T04,
     границы диапазонов. Перебор границ обязателен, случайная часть — с фиксированным seed.
   - Отрицательный контроль через `inject_error`.
   - Применить к 24 `unproven` B001 с объявленными выходами. Прошедшая функция получает
     статус `replaced` с видом доказательства `synthetic` и входит в флаг пакета. Если перебор
     невозможен — причина в таблице.
3. **Журналы.** Подробная строка расхождения — только для первых 20 расхождений на замену
   за процесс, дальше только точные счётчики. Сравнить размер журналов до и после на
   отрицательном контроле B001.
4. **`smoke.ps1`.** Ожидание завершения реплея должно учитывать ротацию журнала: без лишних
   120 с и без одновременных `timeout=true` и `complete=true`. Проверить на сценарии с
   ротацией.
5. **Общие флаги пакета.** `replacement.h` не должен содержать имён конкретных пакетов.
   Пакет объявляется в своём файле, флаги `--pvz_native_<пакет>` и `_compare` создаются из
   объявления. Флаги B001 сохраняют имена и поведение.
6. **Маркер завершения.** Пять проверок завершения в `scripts/check_*` принимают
   `PvZ (frame )?replay completed`, а производный `.checker.log` больше не создаётся. Это
   разрешено владельцем. Других изменений в `check_*` нет.
7. **Шаблон.** Обновить `replacement-howto.md`: какой вид доказательства выбирать (сравнение
   в игре, синтетика, трасса отрисовки, снимки) и как заводить новый пакет. Добавить правило
   хронометража: таймер — до начала разбора, отдельно для заглушек и остальных функций.

## Критерии приёмки

- [ ] Трасса отрисовки: два прогона без замен совпадают на пяти сценариях; B001 включён
      против выключенного — совпадают или расхождения объяснены; искусственная ошибка в
      рисующей замене найдена с шагом и вызовом.
- [ ] Синтетика: у каждой из 24 функций есть статус с числом случаев и отрицательным
      контролем либо причина, почему перебор невозможен.
- [ ] Журнал отрицательного контроля B001 уменьшился, счётчики точные (размеры до и после
      в отчёте).
- [ ] `smoke.ps1` с ротацией журнала: нет лишнего ожидания, нет одновременных `timeout` и
      `complete`.
- [ ] В `replacement.h` нет имён пакетов; флаги B001 работают как прежде.
- [ ] Diff `check_*` — только маркер завершения; `.checker.log` не создаётся; регрессии T12 —
      276/276 без флагов и с `--pvz_native_b001=true`.
- [ ] `.\build.bat test` проходит.
