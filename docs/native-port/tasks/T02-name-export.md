# T02. Экспорт имён в инструменты и код

**Этап:** знание · **Зависит от:** T01 (принятая) · **Объём:** малый · **Меняет поведение игры:** нет

## Цель

Сделать имена из T01 доступными там, где с ними работают: в дизассемблере, в коде порта и
в журналах. Codegen не переименовывать (см. «Открытые решения» в README).

## Входы

`docs/native-port/data/xbox-names.csv` (из T01), `src/*.cpp` с `REX_HOOK_RAW(sub_X)`,
`.cache/pvz-image.bin`.

## Что сделать

1. `scripts/export_xbox_names.py`: из CSV получить
   - скрипт разметки для Ghidra (`research/cross-platform/xbox-names.ghidra.py`, Jython/PyGhidra):
     имена функций, комментарий с уровнем уверенности;
   - `src/xbox_names.h`: `namespace pvz::fn { inline constexpr uint32_t Board_Update = 0x82…; }`.
     High и medium; у medium в комментарии строки — `// medium: <признак>`. Имена —
     C-идентификаторы; перегрузки различать суффиксом по сигнатуре. (Изменено при приёмке
     T01: high всего 6, экспорт только high бесполезен.)
2. Для каждого `REX_HOOK_RAW(sub_X)` в `src/`, у которого есть имя high, добавить или
   исправить комментарий `// Class::Method` в той же строке или над ней. Код хуков не менять.
3. Если комментарий в `src/` противоречит имени high, не исправлять молча: перечислить в отчёте.

## Результат

`scripts/export_xbox_names.py`, `src/xbox_names.h`, правки **только комментариев** в `src/*.cpp`,
`docs/native-port/reports/T02.md`.

- [ ] `.\build.bat test` проходит; `src/xbox_names.h` подключается без предупреждений (можно — в тесте).

- [ ] Скрипт Ghidra применён хотя бы к одному проекту; в отчёте — снимок или вывод с примером переименованных функций.
